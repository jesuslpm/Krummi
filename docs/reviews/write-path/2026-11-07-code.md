<a id="R4"></a>
### R4 — Minor: the performance history states the wrong lifetime for writer integrity checks

**Location:** `docs/performance/plan.md:346`.

**Problem and failure scenario:** the new history row describes O6/O7 as “writer checks once per change and per transaction”. O7 actually shares remembered integrity across transactions for the entire opening, until the engine rewrites a page. A maintainer following this row could expect a fresh check in the next write transaction, including after an external alteration, but the implementation deliberately provides no such revalidation.

**Evidence type:** direct documentation/source comparison. `Snapshot::page_and_code` uses `Integrity::UseRemembered` at `crates/krummi-pager/src/scratch.rs:1024`, as does `Snapshot::run` at line 1082. `integrity_tests::ac_s4_a_write_remembers_a_page_on_its_first_read` asserts that another write does not check again; AC-S6 tests the accepted alteration behavior.

**Requirement:** PRD S2/S3; ODD S4; documentation must accurately describe the changed guarantee.

**Suggestion:** describe integrity checks as remembered per opening and invalidated by engine rewrites, alongside layout checks per change.

### Existing recovery-test race observed during verification

The initial AC-J9 failure is retained as a check failure, even though both reruns passed. The spawned committer panicked at `recovery.rs:25` opening a write with `Io { ... "writes are refused after a failed write; reopen the store" }`; its join then panicked at line 619.

A pre-existing test synchronization race explains this sequence: the test commits `a` at line 595 before installing the transfer hook at line 600. The still-pending transfer of `a` can reach that hook before the spawned committer at line 615 obtains its turn. The main thread passes `released`, opens the empty write and releases `taken` (lines 616–618); the injected transfer fails, and the delayed committer then observes refused writes. Neither this test nor the relevant transfer/hook logic changed from the base. This is a baseline advisory/check limitation, not an introduced finding; a baseline binary reproduction was not performed. A timing change alone does not establish a new storage defect.

Ignored exhaustive acceptance tests and .NET integration tests were not enabled. Linux Cargo checks, benchmarks, historical mutation probes and actual power-plan switching were not run. Existing measurements were checked, not regenerated. The initial full workspace command therefore must not be reported as an all-green run.
