## Findings

### R1 — minor — Beside::Unknown documents a valid tree state as impossible

**Location:** `crates/krummi-tree/src/lib.rs:578`.

The new comment describes a parent without cells as a state “which the tree never leaves.” Such a non-root branch is valid: deleting a child can leave its parent with one child and no separator, and that branch remains when it cannot merge with its sibling. The comment therefore states a false structural invariant next to the code that handles that state.

**Concrete scenario and evidence:** with 2,048-byte keys, a branch holds at most three separator keys. A deletion can remove its last separator through `drop_child` (`lib.rs:1177–1191`), which returns `Underfull`. If combining that branch with its sibling does not fit, `merge_child` returns `Done` without merging (`lib.rs:1128–1153`). The existing helper and regression at `crates/krummi-tree/src/tests.rs:655–708` explicitly describe and reach this valid state at least ten times. That test passed independently in both the workspace debug run and the optimized tree run.

**Impact:** incorrect documentation of the tree invariant, with limited maintainability impact. No runtime failure or data corruption was demonstrated: `append_last` correctly declines an underfull leaf with `Beside::Unknown`, allowing the regular traversal to handle its ancestors. This finding concerns T11's tracking contract and the existing D4 merge behavior, not an unmet product behavior.

**Suggestion:** describe a parent with one child and no separators as a valid post-deletion state, and explain why an underfull leaf requires the regular traversal.

No blocker or major findings, and no functional defects confirmed in the requested range.
