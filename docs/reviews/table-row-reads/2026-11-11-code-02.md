### R1 — original severity: major — Verified resolved

Original finding: `docs/reviews/table-row-reads/2026-11-11-code.md#R1`, “Reading compound keys repeatedly decodes their prefixes.” Resolution claimed fixed in `9941b62`; independently verified at the full head revision above.

**Source evidence:** `crates/krummi/src/table/key.rs:117` records every component's start during the validating walk. `walk_key` at line 125 visits each component once and rejects incomplete elements or trailing bytes. `rows.rs:460` retains these starts for compound keys; a single-column key still uses offset zero without allocating a starts vector. `rows.rs:513` indexes the start by primary-key position and decodes only that component. Reading all fixed-width primary-key columns therefore performs a linear number of component decodes, rather than rescanning every prefix. In `rows.rs:946`, the update collects old values once and reuses them for the merge and equality comparison. Identical updates still return before encoding or modifying the tree (`rows.rs:952`). This addresses original S1 and the efficient-algorithm principle for the E4/E18 supported schemas.

## Dependent invariants and regression assessment

- **Offset bounds and validation:** `encode_key` rejects keys beyond 2,048 bytes; stored tree keys are bounded by node layout validation (`crates/krummi-tree/src/node.rs:139`, including line 156). Consequently offsets fit in `u16` on engine paths. Starts are retained only after all components and complete key consumption validate. The changed equivalence test independently passed for valid, truncated, mutated and extended keys, including escaped zero bytes, multibyte text and mixed variable/fixed components. Direct calls to the helper with keys beyond the contractual maximum do not establish a defect in these supported storage paths.
- **Schema and older rows:** `Reader::new` maps fixed-width columns to their primary-key positions, independently of schema column order. Permitted schema changes preserve the primary-key types and ordering. Existing public tests cover randomized compound keys, forward/backward ranges, mixed schema versions, default values and dropped columns. All selected tests passed.
- **Borrowing and ownership:** fixed-width key values remain decoded copies; variable values continue to borrow row/catalog bytes. `Value::reborrow` (`value.rs:316`) allows the merged update to reuse values from the local old-value vector while it remains alive through encoding. Encoding completes before the tree is mutated; no reference into that vector escapes. `TableRow::into_owned` materializes values before discarding row storage and offsets. The public value-lifetime and older-default tests passed.
- **Errors, scans and no-op writes:** key/row validation still completes before returning a row. The scan passes decode failures through its fused error path (`ranges.rs:100`); write-side damage retains transaction failure handling. An identical update still avoids writes and upgrading an older row. Changed updates encode and check final row size before `set`, retaining public validation precedence and absence of effects. Damage, precedence, partial-update, old-schema and no-op behavior tests passed.

The previous report's coverage limitation remains: the public damaged-page tests can fail at checksum validation before malformed encoded values reach the row checker. Static inspection and the selected tests found no regression here; this follow-up does not claim exhaustive experimental coverage of malformed rows with valid checksums.
