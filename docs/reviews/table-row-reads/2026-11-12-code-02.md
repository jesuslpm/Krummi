### R1 — Major — Update patch adds quadratic work for wide compound primary keys — Verified resolved

**Lineage:** [2026-11-12-code.md#R1](2026-11-12-code.md#R1), claimed fixed in [the resolutions](2026-11-12-code-resolutions.md) by `c873418`; independently verified through the reviewed head.

**Source evidence:** `crates/krummi/src/table/rows.rs:301–304` builds a membership vector from the existing `key_columns` indices. Each `FastColumn` receives its corresponding flag at lines 305–314. The filter at line 515 now performs a single indexed flag lookup instead of searching `key_columns` for each supplied column. Building the added metadata takes O(n + k); each patch traversal takes O(n) for n live columns and k primary-key columns. This removes the repeated membership scans that established R1. Existing schema-construction searches are outside the per-update traversal and were already present at the base.

**Dependent invariants:** `Reader::check` constructs one `Checked.values` entry per live column; `slots`, the membership vector and `fast` likewise have exactly that length. The new indexing uses this same schema position. Membership comes from all primary-key columns, including variable-width ones; it does not reuse `in_key`, which deliberately identifies only fixed-width key columns omitted from stored rows. Schema changes reconstruct the reader (`catalog.rs:168–170`), so dropped columns and renamed keys receive current flags. The old-version fallback, prior normalization and full validation of the replaced row (`write_row`, `rows.rs:1303–1371`) remain intact. Identical updates still return before writing; changed values still use the existing patch encoder and located overwrite/fallback paths. No encoding or page mutation implementation changes in this fix.

**Independent reproduction:** rebuilt the head release library and recompiled the original report's probe from the existing temporary `target/review-table-row-reads/changed.rs` into a new `followup-changed.exe`. Its timing algorithm and assertions match the report's appendix (the existing file additionally drops the stored row and clears the input after checking it). SHA-256 of the executed source: `8bba8b4fa846eccf8016695e582ba64935b9117a3ab1acdf388dd52914d5b9e0`.

The probe uses the original supported layout: nullable string first, k mandatory bool key columns, nullable i64 last. The control supplies the unchanged first variable column to force full merging. Both paths change the integer; 100 warm-up pairs, 4,000 updates per measurement, median of three alternating rounds. It checks the final integer and every key column.
