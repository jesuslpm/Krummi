## Pre-existing advisory

The low-level writer caveat already recorded in ODD L9 remains at the base: `flush_locked` considers read snapshots in `state.live`, not `state.writer` (`scratch.rs:649–656`). Directly publishing through `ScratchWriter` and then continuing to read its initial snapshot while transferring that page can expose newer store bytes; retaining a store reference could violate shared-write preconditions. The old lookup also discarded versions newer than that snapshot and read the Pager. This is source-based evidence of an existing low-level limitation, not an O2 regression or an open finding in this range. No such post-publication read was found in the consuming public transaction commit path; no reproduction was executed.
