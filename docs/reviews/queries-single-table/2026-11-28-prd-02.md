<a id="R4"></a>
### R4 — major — Floating-point aggregate admissibility lacks a usable accuracy contract

**Status:** still open; the resolutions explicitly leave it pending a product decision.

**Section / IDs:** Product decisions / CU12, CU23; AC-CU7; inherited AC-CS1.

**Evidence:** `docs/prd/krummi/queries/queries-single-table.prd.md:35` still permits IEEE 754 floating-point sums and says they may vary “en sus últimos bits” by plan. Line 46 still requires “una tolerancia relativa de 10⁻⁹”. AC-CU7 at lines 301–304 depends on that contract. The inherited differential test compares alternative plans with a full-scan reference (`docs/prd/krummi/queries/queries.prd.md:215`–220).

The original counterexamples were reproduced with binary64 arithmetic in a file-free Python probe:

```text
(1e20 + -1e20) + 1 = 1
(1e20 + 1) + -1e20 = 0

(1e308 + 1e308) + -1e308 = infinity
(1e308 + -1e308) + 1e308 = 1e308
```

These differences exceed the stated tolerance and are not limited to the last bits. Relative tolerance alone also leaves comparison against zero, NaN and infinities undefined. The correction log acknowledges the product decision but does not settle it.

**Allowed readings:** accept ordinary IEEE reductions in any order even when they exceed the tolerance, or require sufficient accuracy against a specified reference. The readings accept different observable results and different test outcomes.

**Suggestion:** Define aggregate admissibility, its reference and exceptional cases without prescribing an implementation algorithm.

## Verified resolutions

All statuses below apply to the reviewed PRD hash above, not to an implemented query engine.

<a id="R1"></a>
### R1 — verified resolved

AC-CU13 now separates query-local budget, deadline, cancellation and spill failures from damage or I/O failures while reading the store (`queries-single-table.prd.md:328`–331). The latter explicitly prevent commit, agreeing with CU18 and T11/T12 (`docs/prd/krummi/transactions/transactions.prd.md:40`–41). The original store-read I/O counterexample therefore no longer requires both commit success and failure.

The source confirms the dependent invariant: `crates/krummi-tx/src/transaction.rs:310`–322 routes failed page reads through `track`; lines 1066–1074 retain the first failure; lines 630–633 reject commit before applying changes. Query-local isolation remains required by CU17/CU18 and AC-CU8; this textual fix does not weaken that requirement.

<a id="R2"></a>
### R2 — verified resolved

CU7 (`queries-single-table.prd.md:30`) now compares compound arguments recursively through the first difference, putting the shorter sequence first when one is an equal prefix. In the original `OR(AND(eq(a,p0),eq(b,p1)),AND(eq(a,p0),eq(c,p2)))` example, either input order must put the `b` branch before `c`. Equal-prefix compounds are explicitly ordered; identical compounds do not need another tie breaker. AC-CU3 retains a determinate canonical-byte expectation.

<a id="R3"></a>
### R3 — verified resolved

The floating-point row (`queries-single-table.prd.md:56`) now applies nearest-even rounding at the subnormal/zero boundary and explicitly says `1e-45` as `f32` gives the smallest subnormal. The coordinator's probe observed `1.401298464324817e-45`; half that minimum, `7.006492321624085e-46`, rounds to zero, while the next binary64 value above that half rounds to the minimum subnormal. Symmetric negative probes give negative zero or the negative minimum; CU8/N4 subsequently canonicalize negative zero. The threshold is read in the explicit nearest-even rule's magnitude context. These probes verify the numeric example, not JSON parser implementation.

<a id="R5"></a>
### R5 — verified resolved

CU5 (`queries-single-table.prd.md:28`) now requires `bind.columns` in column-name byte order. For the original schema ordered `z, a`, the map must emit `a, z`, irrespective of schema or first-use order. CU20 and AC-CU1/AC-CU14 inherit this explicit output rule, removing the original competing canonical forms.

<a id="R6"></a>
### R6 — verified resolved

CU20 (`queries-single-table.prd.md:43`) now distinguishes column descriptors from parameter descriptors and explicitly specifies UUID `order`, string `collation`, and vector `element`, `dim` and boolean `cosine`. UUID columns with RFC and SQL Server order now have distinct descriptions; a vector without cosine emits `cosine: false`.

The attributes match `UuidOrder` and `VectorType` (`crates/krummi/src/table/value.rs:78`–103), `SchemaColumn.ty` and `.collation` (`crates/krummi/src/table/schema.rs:123`–133), and the three `Collation` variants (`crates/krummi/src/table/collation.rs:15`–23). CU5 parameter matching remains independent of UUID order and string collation, so the column-description correction does not restrict parameter matching.

<a id="R7"></a>
### R7 — verified resolved

The starting-state row (`queries-single-table.prd.md:154`) now distinguishes the disk-sort threshold from temporary index sorting without that cap. `crates/krummi/src/table/sort.rs:34` sets 64 MiB, while lines 80–85 trigger spill only when files exist and otherwise continue reserving memory. The inspected test at `crates/krummi/tests/table_index_sort.rs:705`–776 covers reduced-budget temporary sorting without file operations and allocation failure rejecting commit. It was not rerun.

CU17 and AC-CU8 still separately require a memory budget for temporary query sorting; correcting the existing index-sort description does not relax the new query contract.
