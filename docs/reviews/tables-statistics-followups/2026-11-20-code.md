### R1 — Major: the new damage test does not exercise the write sampling path required by S1d

- Location: `crates/krummi/tests/table_statistics/codex.rs:807`, particularly the setup and estimate at lines 809–817.
- Problem: `sampling_in_a_write_skips_the_runs_checksum` invokes the write API, but its sample is built through a separate read transaction. It therefore does not close the requested damage-coverage gap for sampling with a write transaction as the page source, although T2 declares that work complete.
- Concrete scenario and causal evidence: the test loads and closes an existing table with damaged large-value runs, reopens the store, and opens a write. Creating the unrelated tree `previous` does not change the table identity, columns, indexes or emptying counter. All conditions in `WriteTransaction::sample_built` at `crates/krummi/src/table/estimate.rs:755`–`:761` are consequently true, and the test calls `read.build_statistics` at `:764`. It never reaches `self.build_own` at `:792`. The latter passes the write transaction's `self.inner` into `sampled_rows` at `crates/krummi/src/table/statistics.rs:707`–`:709`.
- Observable coverage failure: a regression confined to `krummi_tx::WriteTransaction::run_unchecked` (`crates/krummi-tx/src/transaction.rs:462`–`:484`), such as checking the full run checksum again, would leave this test green. Actual private write sampling or `write.analyze` over the same damaged runs would instead return damage, contrary to the intended ST1 sampling exception. The existing `r13_analyze_in_a_write_of_a_damaged_table_fails_the_write` at `codex.rs:898` corrupts a root page, not a large-value run, and does not cover this case. The private-sampling test at `table_statistics/estimate.rs:203` uses healthy rows.
- Evidence type: verified control-flow argument and inspection of existing coverage. The new test also passed in the independently executed workspace suite. No source mutation or experimental regression injection was performed, and no current production corruption defect is claimed.
- Requirement: S1d, quoting the pending item, «los caminos sin verificar de hojas al azar y de escritura sin prueba de daño»; T2 claims both paths covered. Related product rules are ST1/ST3 and the write error behavior of T11. This is an unmet coverage requirement of the new follow-up work, rather than a claim that this range introduced the underlying write implementation.
- Suggestion: test `write.analyze` over the damaged runs, or force private sampling by adding a column before estimating, and assert that the write can still commit.

No other findings were established. No introduced production correctness defect was demonstrated.
