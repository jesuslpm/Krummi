<a id="R1"></a>
### R1 — major — W12 counts reads outside the writer's measured interval

**Locations:** `crates/krummi-bench/src/worker.rs:904`, `:923`, `:950`; `crates/krummi-bench/voron/Loads.cs:424`, `:426`, `:430`, `:447`. Supporting timing code: `crates/krummi-bench/src/worker.rs:486`.

**Problem and failure scenario:** after the barrier releases the five threads, a reader can run while the writer is descheduled before recording its start. The reader increments its count because `done` is initially false, although those completed reads precede the writer's measured interval. The result divides those extra reads by only `writer.end - writer.start` in Rust or `we - ws` in Voron. In Voron, descheduling between `we = Now()` and publishing `done` also allows reads after the recorded end to be counted. Conversely, Rust publishes `done` before the final timestamp in `parallel`, so descheduling there can extend the denominator after counting has stopped. These scheduling windows can bias W12's metric and its threshold comparison independently of the operations intended to be measured.

**Evidence:** verifiable source/interleaving argument. `parallel` records each thread's own start after the barrier; the barrier does not make those timestamps equal. Readers have no writer-start condition and only test the completion flag. Voron likewise records its writer timestamps separately from its readers' counting condition. These are reachable OS scheduling interleavings, not an assumption that the engine returns incorrect data. The interleavings were not experimentally forced, and their contribution to the committed reports was not quantified.

**Requirement:** K8 and workload W12, incorporated by the specs: “El tiempo es el del escritor, de su primera operación a su última confirmación; cuenta cada lectura individual que termina en ese tiempo”.

**Suggestion:** align counting with the writer's shared measurement interval and test delayed starts and completion publication with controlled scheduling.

<a id="R2"></a>
### R2 — major — Initial report validation accepts an unwritable destination folder

**Location:** `crates/krummi-bench/src/cli.rs:116`. Supporting path: `crates/krummi-bench/src/orchestrator.rs:98`, `:142`, `:153`, `:249`.

**Problem and failure scenario:** pass `--informe` an absent filename under an existing directory that permits metadata lookup but denies file creation, or resides on a read-only filesystem. `check_report` succeeds solely because the parent is a directory. With valid prerequisites, the benchmark builds Voron and performs all measurements before `OpenOptions::create_new` finally fails. With an invalid RavenDB folder, the RavenDB error wins instead of the required earlier report-folder error. An initially unusable destination is therefore handled as a late write failure, potentially losing the report after a long complete run.

**Evidence:** verifiable source argument. The success branch is `Ok(m) if m.is_dir() => Ok(())`; there is no effective write-usability check before `plan::run`. Existing tests cover a missing parent and a parent that is a file, but not a directory without creation permission. A proposed reproduction using a disposable directory with a denied-create ACL was rejected by the execution policy before it ran; no permission change or experimental reproduction occurred.

**Requirement:** S9 / AC-K9 and the ordered validation row “La carpeta donde iría el informe no existe o no se puede usar” → “La orden no hace nada”, with `No se puede usar la carpeta <carpeta>: <causa>.` This row precedes RavenDB validation. The separate final-write-error row covers a failure at completion, not omission of this initial check.

**Suggestion:** check effective destination-folder usability during initial validation and cover both its message and its precedence with an unwritable temporary directory.

<a id="R3"></a>
### R3 — minor — Ctrl+C during finalization can preserve the report and return success

**Locations:** `crates/krummi-bench/src/orchestrator.rs:65`, `:142`, `:153`; `crates/krummi-bench/src/orchestrator/child.rs:64`, `:81`.

**Problem and failure scenario:** press Ctrl+C after the final worker has exited successfully, while its store directories are being removed, the report is being written/synchronized, or the final work subfolder is being cleaned. The handler sets `INTERRUPTED`, but this success path never consults it again. In a reduced run the command can retain the report, print the normal summary and return `0`, although the interruption occurred while the command was still running.

**Evidence:** verifiable control-flow argument. `child::run` checks interruption after observing a process exit only when its exit code is unsuccessful. `execute` writes the report after `plan::run` without another interruption check; `main` performs cleanup and then matches the previously computed success without checking the flag. The finalization-window signal was not experimentally reproduced. Severity is minor because the window is limited to finalization.

**Requirement:** S9 / AC-K9, Ctrl+C validation: “Igual que un fallo: termina los procesos de los motores, borra su subcarpeta y no escribe informe”, message `Banco interrumpido.`, exit code `1`.

**Suggestion:** make report publication and final cleanup participate in cancellation handling, with a test that interrupts during finalization.

<a id="R4"></a>
### R4 — minor — The integration test rejects the valid infinite-ratio result

**Location:** `crates/krummi-bench/tests/run.rs:167`. Supporting implementation: `crates/krummi-bench/src/measure.rs:46` and report rendering in `crates/krummi-bench/src/report.rs`.

**Problem and failure scenario:** in a reduced W12 run, Voron's writer completes its ten writes before any reader completes a counted read, while Krummi completes at least one read. The report correctly renders the ratio as `∞`. However, `a_reduced_run_writes_its_report_and_leaves_no_store` requires `row[7].contains(',')` for every row and fails on that valid result. The benchmark CI job runs this test through `--include-ignored`, so permitted scheduling can produce a false CI failure.

**Evidence:** verifiable source argument. `ratio_text` explicitly returns `∞` for positive Krummi and zero Voron, and the report puts that string in the cell asserted by the test. The allowed zero-Voron case is covered by a passing unit test, but the integration assertion still assumes all ratios contain a comma. This specific end-to-end scheduling outcome was not observed; the attempted end-to-end tests stopped earlier on NuGet access.

**Requirement:** updated AC-K2 and *Salida*: “la razón se muestra `∞` si la de Krummi es mayor que 0”.

**Suggestion:** explicitly validate the permitted infinite-ratio case in the integration assertion.
