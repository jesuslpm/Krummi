## Findings

<a id="R1"></a>
### R1 — major — W12 has no defined result when Voron completes zero reads

- **Section / IDs:** Cargas / W12; product decisions / K7, K8, K11; Salida; AC-K2 and AC-K3.
- **Location:** `docs/prd/krummi/benchmark.prd.md:71`, `:44`, `:209`, `:212`.
- **Evidence:** W12 counts “cada lectura individual que termina en ese tiempo” during the writer's interval. Neither W12 nor K8 requires a minimum number of completed reader operations. K7 specifies “razón Krummi / Voron ≥ 0,80, con los valores sin redondear”. Salida requires “La razón Krummi / Voron lleva dos decimales con coma, **truncada**, no redondeada”; reduced runs retain the other columns unchanged.
- **Problem:** starting the threads together does not guarantee that a reader finishes before the writer finishes. In particular, the reduced writer performs only ten writes. Voron's W12 metric can therefore be zero without any missing key, checksum mismatch or engine failure. `K/0` and `0/0` have no finite ratio to truncate. K7's alternative comparison `K >= 0.80 * V` would pass any nonnegative K when V is zero, but the required ratio column has no specified representation. This affects ordinary reduced reports as well as the treatment of a full run with zero reader progress.
- **Permitted readings:** complete the report using a special ratio representation and evaluate thresholds through the inequality; or treat the measurement as invalid, producing a failure or an unavailable result. These produce different report bytes and can produce different exit codes. Neither choice is delegated to implementation.
- **Static corroboration:** `crates/krummi-bench/src/measure.rs:45` already chooses `∞` when K is positive and `0,00` when both metrics are zero. The test source at `:121` explicitly mentions W12 reduced runs with no completed read and asserts those choices at `:122` and `:123`. This corroborates the missing product rule; the test was read, not executed, and those implementation choices do not settle the PRD.
- **Suggestion:** define zero-denominator output and threshold/error behavior, and include both zero/zero and positive/zero cases in AC-K2/AC-K3.

<a id="R2"></a>
### R2 — minor — AC-K1 refers to size-table cells that do not exist

- **Section / ID:** Criterios de aceptación / AC-K1, with K9 and Salida.
- **Location:** `docs/prd/krummi/benchmark.prd.md:280`, `:46`, `:206`.
- **Evidence:** AC-K1 requires “`no aplica` exactamente en las celdas de canopydb y fjall de W19 a W22, en las dos tablas.” K9 only measures sizes after W1, W2, W3, W14, W15, W17, W19 and W21. Salida explicitly gives the size table one row per K9 workload.
- **Problem:** W20 and W22 have no size-table rows or cells. A literal assertion for all four workloads in both tables conflicts with the specified size-table shape. The intended intersection is understandable, so this is a clarity defect rather than an implementation blocker.
- **Suggestion:** specify W19–W22 in the operations table and W19/W21 in the size table, or explicitly restrict the assertion to rows present in each table.

<a id="R3"></a>
### R3 — minor — Reduced W17 needs an explicit final partial-batch exception

- **Section / IDs:** Product decisions / K11; Cargas / W17; AC-K5.
- **Location:** `docs/prd/krummi/benchmark.prd.md:48`, `:76`, `:294`.
- **Evidence:** K11 says “Los tamaños de las claves, los valores y las escrituras y el número de hilos no cambian.” W17 specifies “en escrituras de 256” but its reduced quantity is “64 valores”.
- **Problem:** exactly 64 values cannot fill a 256-value write. The usual interpretation allows one final partial write, but the blanket preservation of write sizes does not say that 256 is a maximum rather than an exact size. A strict reading conflicts with the reduced total checked by AC-K5. The normal partial-batch interpretation makes the intent recoverable, so this is minor.
- **Suggestion:** clarify that the nominal batch size is preserved and the final batch may contain the remaining values, including a single 64-value batch for reduced W17.
