### R2 — major: an aborted schema identity can alias another schema and return another column's value

- Location: `crates/krummi/src/table/rows.rs:207` (`SchemaId`), with the binding guard at `crates/krummi/src/table/projection.rs:353` and cache-key construction at `:521`.
- Requirement: S1 / PY1, PY3 and AC-PY5. PY1 requires «el de una escritura abandonada nunca coincide con otro»; binding another schema must fail with `DifferentSchema`.
- Evidence type: executed deterministic reproduction using the existing identity-generator test hook, plus the source chain below.

`SchemaId` contains only the store serial, table identity and random schema state. The state generator's collision predicate checks the transaction's persisted history (`crates/krummi/src/table/catalog.rs:657`), which no longer contains an aborted write's state. A projection can outlive that aborted write. If the generator repeats its state for another change, both schemas have equal `SchemaId`. Binding accepts the wrong schema, and caching by that identity plus live-column positions also aliases different lists whose columns occupy the same positions.

Reproduction: create `t(id)`; in write A add `a: i64` with state 40, prepare `[a]`, and abort. In write B add `b: i64` with the same state 40 and a different column identity, then insert `id = 1, b = 77`. The old projection binds and returns 77 as `a`, although the new schema has no `a`. Preparing `[b]` returns the cached preparation for `[a]`.

The following source was passed directly to `rustc` on stdin, linked against the current Cargo-built library:

```rust
use krummi::{Column,Schema,Store,StoreOptions,TableMode};
use krummi::table::value::{ColumnType,Value};
use krummi::table::testing::with_identity_source;
fn ids(values: Vec<u64>) -> impl FnMut(&mut [u8])->krummi::Result<()> {
    let mut next=values.into_iter();
    move |out| { out.copy_from_slice(&next.next().expect("identity source exhausted").to_le_bytes()); Ok(()) }
}
fn main() {
    let store=Store::open_temporary(&StoreOptions::default()).unwrap();
    let schema=Schema::new(vec![Column::new("id",ColumnType::I64).not_null()],&["id"]);
    let mut seed=store.write().unwrap();
    with_identity_source(ids(vec![10,20,30]),||seed.open_table_with("t",TableMode::CreateNew(&schema))).unwrap();
    seed.commit().unwrap();
    let mut a=store.write().unwrap();
    let ta=a.open_table("t").unwrap();
    with_identity_source(ids(vec![40,50]),||a.add_column(&ta,&Column::new("a",ColumnType::I64))).unwrap();
    let old=a.projection(&ta,&["a"]).unwrap();
    let old_column=old.column::<i64>(0).unwrap();
    drop(a);
    let mut b=store.write().unwrap();
    let tb=b.open_table("t").unwrap();
    with_identity_source(ids(vec![40,60]),||b.add_column(&tb,&Column::new("b",ColumnType::I64))).unwrap();
    b.insert_row(&tb,&[("id",Value::I64(1)),("b",Value::I64(77))]).unwrap();
    let row=b.get_row(&tb,&[Value::I64(1)]).unwrap().unwrap();
    let bound=old.bind(&row).unwrap();
    println!("aborted projection [a] binds to new schema [b]: true");
    println!("old [a] reads new [b]: {:?}",bound.get(&old_column));
    let new=b.projection(&tb,&["b"]).unwrap();
    println!("new [b] shares cached [a]: {}",new.same_as(&old));
    assert_eq!(bound.get(&old_column),Some(77));
    assert!(new.same_as(&old));
}
```


Executing the probe exited 0 and printed:

The assertions confirm the defective behavior; the required result is refusal to bind the stale projection and no cache alias. Without the hook this requires a repeated random 64-bit state and is extremely unlikely; the experiment establishes the failure when a collision occurs, not its natural frequency. No memory-safety or on-disk corruption claim is made. Existing tests already inject known-identity collisions (`crates/krummi/tests/tables.rs:1229`), but AC-PY5's new test does not force repetition of an aborted state. The generator predates this range; the new projection/cache reliance on its identity introduces this observable failure.

Suggestion: maintain an unambiguous schema incarnation while projections or copied rows can still observe it, including projections not retained after the cache limit is reached.
