### R2 — major, verified resolved: an aborted schema identity can alias another schema and return another column's value

- Original ID: `docs/reviews/tables-projection/2026-11-16-code.md#R2`.
- Fix: `3a548b28073733f825c71965be52319653f84f65`, verified at the reviewed head.
- Requirement: S1 / PY1, PY3 and AC-PY5; PY1 requires «el de una escritura abandonada nunca coincide con otro».
- Relevant locations: `crates/krummi/src/table/catalog.rs:570`, `:580`, `:627`, `:663`, `:666`; `crates/krummi/src/table/projection.rs:104`, `:163`, `:392`, `:562`.
- Evidence: source/invariant trace, the committed forced-collision regression test, and an independently compiled deterministic probe extending the original reproduction to uncached projections and copied rows.

The store now retains table identities issued during creation or removed by deletion, and schema states issued by changes, keyed by table. These sets survive transaction aborts. Creation rejects retired table identities; changes reject both retired per-table states and identities in the table's persisted history. Consequently, a later schema cannot repeat an aborted schema's `(store, table, state)` identity. Binding compares that identity before selecting a read plan; the projection-cache key contains the same identity, preventing the original cache alias.

Independent reproduction and regression verification:

1. `ac_py5_a_repeated_identity_never_aliases_a_schema` passed. It repeats the original state-40 aborted-change scenario and forces reuse of a deleted table's identity/state after reopening the files. Both cases reject stale binding with `DifferentSchema`, avoid sharing the stale cached preparation, and preserve correct current reads.
2. A stdin-compiled probe filled all 1,024 cache slots using nonempty subsets of 11 columns, then prepared an uncached `[a]` projection in an abandoned write with state 40 / column 50. It copied a row with `a = 55` before aborting. The next write attempted state 40 again and correctly redrew state 60 / column 70 for `[b]`, then wrote `b = 77`. The old projection rejected the new row, the new projection rejected the copied old row, and their respective correct reads remained 55 and 77. This checks identity protection independently of retained cache entries and proves copied rows retain their own schema identity.
3. With the cache still full, another abandoned write created table identity 100 / column 110 / state 120. A subsequent creation forced draws `[100, 101, 110, 120]`: identity 100 was rejected, identity 101 was used, and the abandoned projection rejected the new row despite equal column/state numbers.

The probe used only an in-memory store; no probe source file was created. It was compiled against the library freshly built by this review's Cargo test command:

```text
rustc - --edition=2024 --extern krummi=target/debug/deps/libkrummi-63916db6d3259c1c.rlib -L dependency=target/debug/deps -o target/tables-projection-followup-identity.exe
```

Execution exited 0 and printed:

```text
uncached projection + copied aborted row: repeated state rejected; old=55, new=77

```

Dependent invariants checked outside the changed lines:

- Initial schema states are written into history before creation returns a usable handle (`catalog.rs:579–593`); changes consult that history. Initial states therefore need no separate retired-schema insertion while their table exists. After deletion, rejecting the table identity protects every schema of that table.
- Rename with overwrite reaches `drop_table` for its destination (`catalog.rs:434–436`), so it also retires the deleted identity. Rename and empty preserve the surviving table's identity/schema as required.
- One writer turn serializes identity selection and retirement (`crates/krummi/src/lib.rs:209–216`); each retired-set lock protects a single operation and is released before random generation or catalog access. Read transactions do not mutate these sets.
- Reopening creates a fresh store serial; projections cannot outlive their store. Retired sets need no on-disk persistence. The catalog/history/row format is unchanged.
- Validation and no-op schema changes return before retirement. Failed/aborted mutations may conservatively retain identities; this does not modify persisted state or weaken existing failure handling. Existing generator-failure, history, identity-redraw, rename/delete, no-op and maximum-version tests all passed.
- Retired states are scoped by table, preserving the permitted reuse of state/column numbers in different tables; the existing D6 deterministic test passed. The sets are independent of the 1,024-entry projection cache. Their documented lifetime growth is not a newly demonstrated defect.
