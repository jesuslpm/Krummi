### R1 — Unbounded text and bytes filters discard all matching rows

**Original severity:** blocker. **Follow-up status:** verified resolved.

**References:** `docs/reviews/table-scans/2026-11-26-code.md#R1`; fix `19f1e7841aa40b43dbe5d1028a371fbc4568a134`; `crates/krummi/src/table/filter.rs:239`; regression test `crates/krummi/tests/table_vector_indexes/exact.rs:984`.

**Source verification.** Previously, mapping two unbounded limits invoked no value conversion, so even text/bytes acquired a rank predicate. `meets` then rejected every non-null value because `element_rank` does not support those types. The fix first gates rank construction on `ColumnType::fixed_width()` (`value.rs:128`). Text and bytes now use element encoding, and `Test::passes` accepts both unbounded limits. Null rejection still occurs before dispatch (`filter.rs:338`). This restores S4/S6, including: “Los recorridos deben devolver exactamente las mismas filas, en el mismo orden, y las mismas comprobaciones de daño.” It also restores VI7/AC-VI13.

**Independent experimental verification.** The new public-API regression test passed all eight combinations of text/bytes, secondary index present/absent, and disk/temporary store; it asserts the ordered keys `[1, 3]` while excluding the null row. The complete `exact::` subset passed, including SQL null semantics and the fixed-width ordering matrix.

The coordinator also compiled a separate five-test public-API harness from stdin against the current checkout's freshly built `target/debug/libkrummi.rlib`, producing only `target/table-scan-followup-review.exe`. It reconstructs the original report's four failing configurations and I64 control, adding committed-read and vector-index fallback checks:
