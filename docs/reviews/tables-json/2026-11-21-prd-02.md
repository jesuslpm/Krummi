### R1 — Incompatible backing memory for included JSON — Verified resolved

- Original finding: [2026-11-21-prd.md#R1](2026-11-21-prd.md#R1), severity **blocker**.
- Section / IDs: Product decisions / JS5; Acceptance criteria / AC-JS7.
- Reviewed fix: the JSON PRD version identified above.

**Correction and original reproduction.** JS5 now distinguishes “de la fila, al leerla por su clave, al recorrerla o con una proyección, y de la entrada del índice, sin leer la fila, al leerlo como columna incluida” (`docs/prd/krummi/tables/tables-json.prd.md:50`). AC-JS7 correspondingly requires pointers into “la memoria de la fila leída” for row access and “la memoria de esa entrada, sin leer la fila” for included access (`:241–247`). The original impossible requirement that both routes point into “la memoria de la página de la fila” is removed.

The original source reproduction still establishes the distinction: `IndexEntry<'t>.included` is an index-value slice (`crates/krummi/src/table/index_scan.rs:143–144`); included access decodes `row(self.included)` (`:225–230`); the entry scanner obtains only the index key/value pair (`:288–292`). IX8 explicitly requires “Las entradas se leen sin leer las filas” (`docs/prd/krummi/tables/tables-indexes.prd.md:53`). The revised criterion agrees with this route and no longer requires a table-row lookup to obtain its backing memory.

**Dependent invariants and regression checks.** JS5 preserves transaction-bound references under B9/E16, ownership for copied rows, and owned decoding only when a string contains stored escapes. IX8 still excludes binding entries to projections or producing owned entry copies. Existing source retains transaction-bound `Value<'t>` access (`index_scan.rs:218`; `rows.rs:1009`) and independently owned copied rows (`rows.rs:989`, `:1029`). Existing mutation lifetime examples (`rows.rs:48–125`) were inspected, not executed.

The row wording is consistent with logical rows, including defaults: the parent defines a row as “un valor para cada columna del esquema” (`tables.prd.md:34–36`), and E11 includes defaults for columns added after storage (`tables-schema.prd.md:46`). `Stored::Row` retains catalog defaults separately from its encoded row bytes (`rows.rs:978–989`), and projections preserve `Access::Default` (`projection.rs:209–211`). The corrected criterion refers to the memory of the row read and to existing string checks, rather than reintroducing the removed physical row-page requirement. It does not require rewriting old rows or copying their defaults.

JS6's restriction on navigation reading pages does not force a table-row read for included JSON: navigating the already borrowed contiguous document requires no additional page reads, satisfying that restriction and the explicit index-only requirement. No storage-format, validation-order or transaction-mutation change is introduced by this correction.

**Acceptance evidence inspected.** The cited existing test pattern is concrete: `tests/table_encoding.rs:1518–1522` checks a string pointer into row bytes; `tests/table_projections.rs:233–235` checks projection pointer identity; `tests/table_indexes.rs:957–967` checks borrowed included values. These sources support the revised acceptance check; they were not executed and do not constitute implementation tests of future JSON accessors.
