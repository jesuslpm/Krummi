### R1 — minor — Sampling rate targets are still described as hard limits in the HTML

- **Previous ID:** [2026-11-21-code.md#R1](2026-11-21-code.md#R1), retained by [2026-11-21-code-02.md#R1](2026-11-21-code-02.md#R1).
- **Status:** partially fixed; still open.
- **Location:** `docs/design/tables/15-query-profile-and-tuning.html:195`; supporting text at lines 169–172 and 203–206; chart computation at lines 555–563.
- **Problem:** the companion still says that, during the first seconds, an entry “cannot keep more than R rows per second” and that its start is “flattened to R”. The new caveat labels the global B curve as idealized, but does not correct the entry-rate claim. The page's existing expected-values disclaimer at line 120 does not resolve this: the chart's own expected rate can exceed R at startup.
- **Concrete scenario:** select the default entry rate `λ = 100`, `R = 10`, `T = 2000`, `p_min = 0.0001`, `τ = 86400`. At the first plotted point, `t = 0.01 s`, `cOf(t) = max(1, λt) = 1`; the decayed-count probability is 1, so `pC = min(10/1, 1) = 1`. The plotted expected rate is `λpC = 100 rows/s`, ten times R. At `t = 0.1 s`, it is still 100 rows/s. With the selectable `λ = 10000`, the first plotted expected rate is 1000 rows/s, also above R. Thus even the immediate-update idealization does not support the remaining assertion; the actual proposed snapshot delay adds the original startup overshoot.
- **Evidence type:** executable reproduction of the existing chart model, plus independently checked source arithmetic. The coordinator extracted the actual `entryModel()` function into Node stdin, supplied the original `logGrid` expression and simple input-value stubs, and asserted that the first capped-rate point exceeds R. Results were `{lambda:100, R:10, time_seconds:0.01, expected_rows_per_second:100}` and `{lambda:10000, R:10, time_seconds:0.01, expected_rows_per_second:1000}`; both assertions passed, exit 0. No browser or implemented profiler is needed to establish this documentation contradiction.
- **Original reproduction rechecked:** `10000 × 0.1 = 1000` rows can precede the first snapshot; the idealized continuous first-second expression remains `10 × (1 + ln(10000/10)) = 79.07755278982137`, also above ten. The corrected Markdown now explicitly acknowledges the former and retains the latter.
- **Requirement:** internal consistency of the design and its illustrated companion within the original reviewed range; no JSON S#/AC applies. This is the unresolved portion of the original finding, not a new defect attributed to the fix range or an engine failure.
- **Suggestion:** qualify the remaining HTML rate-limit statements as targets and describe startup overshoot consistently with the corrected Markdown and chart formulas.
