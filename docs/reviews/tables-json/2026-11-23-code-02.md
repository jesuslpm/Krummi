### R1 — minor — Sampling-rate explanation still contradicts selectable chart inputs

- **Previous ID:** [2026-11-21-code.md#R1](2026-11-21-code.md#R1), retained in both follow-up reports above.
- **Status:** partially fixed; still open because the correction introduces a documentation regression within the same text/model consistency finding. The earlier hard-quota assertions are corrected.
- **Location:** `docs/design/tables/15-query-profile-and-tuning.html:199`; supporting new assertions at lines 169–171, 196–198, 205–207 and 234–235; controls at lines 178 and 182; dependent model at lines 559–572.
- **Problem:** the replacement explanation applies the hot-entry startup formula and R plateau unconditionally. It now says an entry keeps more than R rows in its first second, gives `R(1 + ln(rate/R))` as its expected count, and says it keeps about R rows/s after that second. These statements do not hold when the entry's execution rate is below R, an explicitly selectable case.
- **Concrete failure scenario:** choose `Rate of the entry = 1 per second`, keep `R = 10`, `T = 2000`, `p_min = 0.0001`, and `τ = 86400`. During the first second, `nDecay(t) < 1`, so `pB = 1`; `cOf(t) = 1`, so `pC = min(10, 1) = 1`. The model therefore keeps one expected row over that second and remains at one row/s at two seconds. The new prose instead promises more than ten rows, its formula gives `10(1 + ln(1/10)) = -13.025850929940454` rows, and its claimed plateau is ten rows/s. Expected retained rows cannot be negative or exceed all executions in this case.
- **Evidence type:** executable reproduction of the actual chart model, corroborated by a source-level causal argument. The coordinator extracted `entryModel()` and the original `logGrid` declaration from the HTML, supplied input-value stubs, and ran them through Node stdin. For this case, all capped-rate points were at most one row/s; the first point was `[0.01, 1]`, the point near two seconds was `[1.9756973001761204, 1]`, and the newly documented expression was negative. Assertions passed, exit 0. The delegated reviewer independently reached the same conclusion from source.
- **Attribution:** commit `834fb9e` adds these unconditional claims to the HTML. The similar formula already present in Markdown is not a separate new finding. This report retains R1 because the correction still leaves the explanation inconsistent with its model, rather than opening an unrelated review.
- **Requirement:** internal consistency of the design and its interactive companion; no JSON S#/AC applies. This remains a minor documentation defect, not an engine failure.
- **Suggestion:** qualify the startup formula and plateau for entries where the R/c factor actually limits sampling, and describe slower entries using the minimum with their original sampling probability.

No separate new finding or functional regression was established. No open product questions arise within this follow-up scope.
