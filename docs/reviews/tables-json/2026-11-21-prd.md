## Findings

Two findings remain open: one blocker and one minor.

<a id="R1"></a>
### R1 — blocker — AC-JS7 requires incompatible backing memory for an included column

- **Section / ID:** Acceptance criteria / AC-JS7; `docs/prd/krummi/tables/tables-json.prd.md:241`.
- **Problem:** The criterion includes reading JSON “como columna incluida de un índice” while requiring its document and escape-free string to “apunten a la memoria de la página de la fila”. The included value is stored in the index entry. Its reference cannot simultaneously point into the original table row while preserving the inherited index-only read contract.
- **Evidence:** IX8, `docs/prd/krummi/tables/tables-indexes.prd.md:53`, requires: “Las entradas se leen sin leer las filas”. JS5 adopts IX8. Existing `IndexEntry.included` holds the entry's included bytes (`crates/krummi/src/table/index_scan.rs:143`); included-column access reads that buffer (`crates/krummi/src/table/index_scan.rs:225`), independently of the table row. The coordinator verified this evidence against source.
- **Consequence:** An index-only implementation fails the literal pointer assertion; obtaining the original row's backing memory requires reading the row, violating IX8. The criterion cannot be implemented and tested as written together with its inherited contract.
- **Suggestion:** Specify the backing storage for each read route and assert that included JSON borrows the index entry without copying or reading the table row.

<a id="R2"></a>
### R2 — minor — The claimed cross-document annotations are absent

- **Suggestion:** Complete the announced annotations in the affected documents and their translations before declaring the PRD finished.
