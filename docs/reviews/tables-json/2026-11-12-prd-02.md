### R1 — Define the copy contract for decoded JSON strings — Verified resolved

- Original finding: [2026-11-12-prd.md#R1](2026-11-12-prd.md#R1), severity **major**.
- Section / IDs: child allocation 7.5 / typed extraction; Output; annotations to root D11 and AC20; inherited T16 and B10.
- Claimed disposition: `fixed`. Independently verified against the corrected artifact versions above. There are no `dismissed with evidence` entries in the supplied resolutions.

**Contract correction.** `docs/prd/krummi/tables.prd.md:181–185` now requires “sin copiarlo si la cadena no tiene escapes y decodificado en una copia propia de la aplicación si los tiene”, explicitly declares “una excepción a D11 y AC20” and preserves “el documento entero se lee siempre sin copia”. The same rule appears in Output (`:288–290`) and annotations to the root (`:459–463`). Root `docs/prd/krummi/krummi.prd.md:129–133` carries the corresponding dated D11/AC20 exception. Q1's choice “A” is recorded in the authoritative PRD and resolutions; this review verifies the resulting contract, without independently reconstructing the earlier user conversation.

**Original reproduction rechecked.** Stored form v1 retains mandatory escapes (`docs/design/tables/13-json-column-storage.md:698–700`). For stored text `{"x":"a\nb"}`, the decoded value has bytes `61 0a 62`, absent as a contiguous subslice of that document. The old universal no-copy reading could not produce that ordinary decoded string from a stored slice. The corrected exception permits its own decoded allocation while the whole document remains borrowed. No storage-format change or read-time mutation is needed.

The coordinator executed an in-memory Python representation check using `json.loads` and, for these selected cases, `json.dumps(..., ensure_ascii=False, separators=(',', ':'))`. All nine assertions/cases passed:

| String case | Normalized representation | Corrected extraction contract |
|---|---|---|
| Original newline example | Retains `\n`; decoded bytes absent from the document | Owned decoded string |
| Plain `abc` | Raw UTF-8 | Borrowed stored slice |
| Embedded quote | Retains `\"` | Owned decoded string |
| Backslash | Retains `\\` | Owned decoded string |
| U+0000 | Retains `\u0000` | Owned decoded string |
| Input `\u0061` | Raw `a` | Borrowed stored slice |
| Input `\/` | Raw `/` | Borrowed stored slice |
| Escaped surrogate pair | Raw UTF-8 character | Borrowed stored slice |
| Empty string | Empty stored string content | Borrowed stored slice |

This models byte representation, not Krummi's future JSON parser or allocation behavior. Escapes removed by normalization are judged by the stored string, consistent with the incorporated Stored form v1 and its zero-copy checks (`:819`).

**Dependent invariants and code.** The exception applies to typed JSON extraction; it does not weaken raw page/tree value reads (T16, B10, V2) or the transaction lifetime of borrowed references (T8/D11). `Value::String(Cow<'a, str>)` already represents borrowed and owned strings (`crates/krummi/src/table/value.rs:297`), and `into_owned` supports independent ownership (`:335–340`). Existing ordinary string decoding still returns `Cow::Borrowed` (`crates/krummi/src/table/row.rs:708–710`). `TableRow::value` returns transaction-bound values (`rows.rs:915–919`), and existing owned rows have a distinct ownership conversion (`:966–977`). The correction does not require these ordinary string reads to start copying.

Existing mutation-lifetime `compile_fail` examples (`crates/krummi/src/table/rows.rs:48–125`) and the test for values surviving their row while their transaction remains valid (`crates/krummi/tests/table_rows.rs:2130–2175`) were inspected, not executed. There is no JSON column variant in current `ColumnType` (`value.rs:40–73`); this is a future child contract, not a claim that JSON extraction is already implemented.
