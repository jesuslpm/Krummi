## Findings

<a id="R1"></a>
### R1 — minor — Incorrect error rule for identifier string writes

- **Location:** `docs/guides/sequences-and-ids.md:234`–235.
- **Problem:** The text says that writing `Value::String` to a UUID/ULID column follows the `MalformedText` rule. Such writes return `WrongType`, regardless of whether the string is a valid identifier.
- **Concrete scenario:** Insert a valid UUID string as `Value::String` into a UUID primary key. The row validator calls `normalize`, which accepts only `Value::Uuid` for that column and returns `WrongType` for the string. Error handling based on the guide's `MalformedText` claim therefore selects the wrong rule; the string is never parsed or stored.
- **Evidence:** Executed public-API doctest in `docs/guides/data-types.md:535`–538 asserts this exact `WrongType` result. Source corroboration: `crates/krummi/src/table/value.rs:392`–444 and `crates/krummi/src/table/rows.rs:398`. Explicit identifier parsing has its separate `MalformedText` behavior in `crates/krummi/src/ids.rs:54`–117.
- **Requirement:** S1, explaining operations and data types accurately.
- **Suggestion:** Distinguish explicit text parsing from writing the resulting `Value::Uuid` or `Value::Ulid`.
- **Status:** Open.

<a id="R2"></a>
### R2 — minor — Vector NaNs are incorrectly listed as normalized

- **Location:** `docs/guides/data-types.md:710`.
- **Problem:** The conversions table extends canonical NaN normalization to vectors, contradicting their validation rules and the guide's own vector example.
- **Concrete scenario:** Insert an F32 vector of the declared dimension containing a NaN. The caller expects a canonical NaN to be stored according to this table, but vector validation rejects the write with `InvalidValue` / `VectorNotFinite` before storing the row.
- **Evidence:** Executed vector doctest in `docs/guides/data-types.md:595`–604 asserts the rejection. `crates/krummi/src/table/value.rs:513`–539 checks finite elements before normalization. Scalar canonicalization is separate at `value.rs:450`–467. The table PRD N4 states: “Ningún vector admite NaN ni infinitos.”
- **Requirement:** S1; documented behavior must agree with table PRD N4 and schema PRD E7/E17.
- **Suggestion:** Limit NaN canonicalization to scalar floats and describe only negative-zero normalization for vectors.
- **Status:** Open.

This documentation inconsistency predates the range and is advisory under the skill's base-defect rule, excluded from the introduced findings and approval decision. Suggestion: qualify the rollback promise to failures before commit and retain the unknown-outcome caveat for commit I/O errors.
