## Findings

<a id="R1"></a>
### R1 — Major: an invalid destination leaves rewritten references behind

- Location: `scripts/docs/move_docs.py:175`; validation at lines 159–166 and directory creation at line 178.
- Requirement: S5 and the explicit function contract at line 155: `Nothing is written when the move is not valid.`
- Evidence: experimental reproduction through the real CLI in a disposable Git repository, confirmed against the complete `move` function.
- Preconditions: tracked `a.md`, a tracked regular file named `blocked`, and `README.md` containing `[a](a.md)`. A manifest requests `a.md` → `blocked/a.md`.
- Failure: `python -I -B <script> move <manifest>` passes validation because `blocked/a.md` does not exist. The rewrite loop changes README to `[a](blocked/a.md)` before creating destination directories. `mkdir` then raises `FileExistsError` because `blocked` is a file; the command exits 1. `a.md` remains at its original path, while README remains modified with a broken link. A tracked manifest containing the source path is also rewritten before the failure.
- Impact: a rejected move dirties unrelated tracked documents and leaves references pointing to files that were never moved. The current invalid-move tests only cover an existing final destination, an untracked source, and duplicate destinations.
- Suggestion: validate destination ancestors and conflicts across the complete move plan before rewriting any file.
- Status: open.

<a id="R2"></a>
### R2 — Major: archiving breaks valid angle-delimited Markdown destinations

- Location: `scripts/docs/move_docs.py:37`, with the related reference-definition handling at lines 40 and 93–101.
- Requirements: S3, especially `No link that worked before the move is broken after it.`, and S5's use of the script for later archiving.
- Evidence: experimental reproduction through the real CLI in a disposable Git repository, confirmed against link parsing and rewriting.
- Preconditions: tracked root `README.md` and `odd/tasks/f.md` containing these valid links:

  ```markdown
  [readme](<../../README.md>)

  [root]: <../../README.md>
  ```

- Failure: `python -I -B <script> archive f tooling` exits 0 and reports `rewrote references in 0 files`. The execution moves to `odd/done/tooling/f.md`, but both destinations remain unchanged. They now resolve to nonexistent `odd/README.md`; the correct destination is `<../../../README.md>`.
- Cause: `INLINE` explicitly excludes angle-delimited destinations. `MD_REFERENCE` captures the angle brackets as filename characters, so the existence check treats the originally valid reference as missing and leaves it unchanged. `check` ignores the inline link and incorrectly reports the reference definition as broken even before the move, so its before/after comparison cannot expose this regression.
- Impact: the reusable archive command reports success while breaking working document links. The comment that this syntax is not used in the current corpus does not establish an exclusion in S3/S5. The migration itself introduced no new broken links among the forms recognized by the checker; this finding concerns a supported Markdown input to future archiving.
- Suggestion: parse angle-delimited destinations and preserve their delimiters when checking and rewriting them.
- Status: open.
