### R1 — Major: destination aliases still allow a rejected move to leave partial changes

- Earlier finding: [2026-11-13-code.md#R1](2026-11-13-code.md#R1). Status: **still open**, partially corrected by `ec5011b`.
- Location: `scripts/docs/move_docs.py:187`, `198–205`; writes and moves at `212–218`.
- Requirement: S5 and the function contract at line 184, `Nothing is written when the move is not valid.` The new whole-plan validation also promises that no destination ancestor is another destination.
- Evidence: independent CLI reproduction on head in a disposable Git repository. The exact original `blocked/a.md` case now rejects the move without changing tracked files or README; the new test's canonical cross-destination conflict also rejects it. However, a root-relative destination with the ordinary `./` prefix bypasses that same validation.
- Reproduction: commit `a.md`, `b.md`, and a README containing links to both. Supply this two-line manifest, with literal tabs:

  ```text
  a.md	./x.md
  b.md	x.md/b.md
  ```

  Run `python -I -B <absolute-script-path> move <manifest>` from that temporary repository. Both destinations are initially absent.
- Causal chain: `destinations` retains `./x.md`, while `Path('x.md/b.md').parents` produces `x.md`. The string membership test at line 202 misses their identity. The rewrite loop changes the README destinations to `x.md` and `x.md/b.md`, then Git moves `a.md` to `x.md`. Creating the parent of the second destination fails because `x.md` is now a regular file.
- Observed result: exit 1, `FileExistsError: [WinError 183] Cannot create a file when that file already exists`, changed README, staged rename of `a.md` to `x.md`, and `b.md` still at its old path. Its rewritten link is broken. Thus the claimed rejection-before-writing invariant remains false under a supported relative-path spelling.
- Suggestion: validate destinations, uniqueness and ancestor conflicts using one consistently normalized path representation before rewriting anything.
