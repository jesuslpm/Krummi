## Findings

<a id="R1"></a>
### R1 — major — Remembered bits do not preserve the verified run's exact extent

**Location:** `crates/krummi-pager/src/pager.rs:392–396`.

The fast path checks the first page number and whether every requested page has a remembered bit. It does not establish that those pages were verified as one run of that exact length. After verifying a three-page value run, its one-page prefix also passes this condition, although the stored checksum covers three pages. The same head is accepted as a standalone page. No bytes need to change between these reads.

**Concrete scenario and reproduced result:** seal and write a valid three-page run in a temporary pager, put it behind `Scratch`, and open a read snapshot. `snapshot.run(first, 1)` initially returns `Damaged`. Read the valid run with `snapshot.run(first, 3)`. Now the same `snapshot.run(first, 1)` returns `Ok`, and `snapshot.page(first)` also returns `Ok`. Independently, `format::verify_run(first, &run[..PAGE_SIZE])` is false, and `Pager::run(first, 1)` still returns `Damaged` because it always verifies.

**Evidence type:** executed reproduction and source argument. The coordinator compiled Rust supplied through stdin against the current pager rlib and ran `target/integrity-snapshot-review-repro.exe`, exit 0, with these assertions:

```rust
use krummi_pager::{Pager, Scratch, OpenOptions, ErrorKind};
use krummi_pager::format::{PAGE_SIZE, HEADER_PAGES, seal_run};

let mut pager = Pager::open_temporary(&OpenOptions::default()).unwrap();
let first = HEADER_PAGES + 4;
pager.ensure_pages(first + 3).unwrap();
let mut run = vec![7u8; 3 * PAGE_SIZE];
seal_run(first, &mut run);
pager.write_run(first, &run).unwrap();
let scratch = Scratch::new(pager);
let snapshot = scratch.snapshot().unwrap();
assert_eq!(snapshot.run(first, 1).unwrap_err().kind(), ErrorKind::Damaged);
snapshot.run(first, 3).unwrap();
assert!(snapshot.run(first, 1).is_ok()); // Wrong: this is not that run.
assert!(snapshot.page(first).is_ok()); // Wrong: this is a value-run head.
```

At the base, every data-file run read went through `format::verify_run`; that function binds the checksum to the exact supplied length (`crates/krummi-pager/src/format.rs:280–286`). `Snapshot::run` explicitly requires one run of exactly `count` pages (`scratch.rs:1033–1037`), and `ReadTransaction::run` promises damage when the pages are not such a run (`crates/krummi-tx/src/transaction.rs:68–77`). The bitmap loses this distinction. The existing test `a_run_is_read_only_whole_and_from_one_place` checks incorrect lengths only while the run resides in scratch (`scratch_tests.rs:273–299`), so it does not catch the fast path after a store read.

**Requirement:** I1/I2, S1/AC-I1, and the inherited complete-run integrity contract associated with V7. I1 states: “Un valor guardado fuera de su hoja, que se comprueba entero, se recuerda y se olvida entero.” A prefix is not the run that passed verification. The PRD does not authorize relaxing the existing invalid-range error behavior.

**Impact boundary:** this demonstrates a substantive internal integrity-contract regression. No wrong result through valid operations of the top-level `Store` facade was demonstrated; P1 excludes direct page access from the product's public contract. This is not evidence of a blocker or of memory unsafety.

**Suggestion:** preserve the verified run's exact identity before skipping its checksum, and test incorrect extents and standalone-page access after the run has reached the store and been remembered.

**Status:** open.

### R2 — minor — A zero-page remembered read panics before validation

**Location:** `crates/krummi-pager/src/pager.rs:393`.

For an in-bounds `first` and `count == 0`, `raw_pages` returns an empty slice. `run_with(first, 0, Integrity::UseRemembered)` then indexes `run[8..16]` before the empty-run check in `format::verify_run`. This panics even with an empty remembered bitmap. The corresponding `Integrity::Check` call and the base implementation return the damage class.

**Evidence type:** executed reproduction and source argument. In the coordinator's Rust stdin harness, `pager.run(first, 0).unwrap_err().kind()` was `ErrorKind::Damaged`; wrapping `pager.run_with(first, 0, Integrity::UseRemembered)` in `catch_unwind(AssertUnwindSafe(...))` caught this panic:

```text
panicked at crates\krummi-pager\src\pager.rs:393:19:
range start index 8 out of range for slice of length 0
```

The harness `target/integrity-review-repro.exe` exited 0 after asserting the differing results. `format::verify_run` rejects an empty slice before inspecting its header (`format.rs:281–286`); the new fast path bypasses that guard. No documented nonzero-count precondition was added to `run_with`.

**Requirement:** preservation of read errors in I2 and *Validaciones y mensajes*; there is no dedicated acceptance criterion for this internal argument.

**Impact boundary:** limited to direct pager access. `Snapshot::run` already rejects zero counts (`scratch.rs:1048–1052`), so a reachable panic through the top-level `Store` facade was not demonstrated.

**Suggestion:** reject an empty run before inspecting its header and verify consistent damage errors under all integrity policies.

**Status:** open.
