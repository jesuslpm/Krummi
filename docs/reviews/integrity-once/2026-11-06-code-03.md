## Open finding caused by the corrections

<a id="R1"></a>
### R1 — major — Reopened: run extent validation disappears when its length mark is replaced

Original ID: `docs/reviews/integrity-once/2026-11-06-code.md#R1`; previously verified resolved in `2026-11-06-code-02.md#R1`.

**Location:** `crates/krummi-pager/src/pager.rs:415–419`; supporting replacement/lookup logic in `crates/krummi-pager/src/checked.rs:112–128,141–143`.

The R3 correction restores bits for every page of a verified run, but makes the exact-length mark optional: `run_length(...).is_none_or(|length| length == count)`. Once another run or node replaces the mark, the remembered bits accept a shorter extent from the same head, including its head as a standalone page. Those fragments did not pass their own integrity check. This reproduces the original R1 result after an unrelated valid read, with no changed bytes or checksum collision.

**Executed reproduction:** in a temporary pager with the default 65,536-slot table, write valid three-page runs at pages `6` and `65542`. Open a snapshot, read the first complete run, and verify that its one-page prefix returns `Damaged`. Read the second complete run through the same snapshot; its first read replaces the shared slot. Now `snapshot.run(6, 1)`, `snapshot.run(6, 2)` and `snapshot.page(6)` all succeed without an integrity check. `format::verify_run` rejects both returned prefixes, and unconditional `Pager::run(6, 1)` still returns `Damaged`.

The coordinator compiled this reader-only harness from stdin against the current pager rlib and ran `target/integrity-review03-snapshot-repro.exe`, exit 0, with these assertions:

```rust
use krummi_pager::{Pager, Scratch, OpenOptions, ErrorKind, CHECKED_SLOTS};
use krummi_pager::format::{PAGE_SIZE, HEADER_PAGES, seal_run, verify_run};

fn main() {
    let mut pager = Pager::open_temporary(&OpenOptions::default()).unwrap();
    let first = HEADER_PAGES + 4;
    let other = first + CHECKED_SLOTS as u64;
    pager.ensure_pages(other + 3).unwrap();
    for (at, fill) in [(first, 7), (other, 9)] {
        let mut bytes = vec![fill; 3 * PAGE_SIZE];
        seal_run(at, &mut bytes);
        pager.write_run(at, &bytes).unwrap();
    }
    let scratch = Scratch::new(pager);
    let snapshot = scratch.snapshot().unwrap();
    snapshot.run(first, 3).unwrap();
    assert_eq!(snapshot.run(first, 1).unwrap_err().kind(), ErrorKind::Damaged);
    snapshot.run(other, 3).unwrap();
    let checks = scratch.pager().integrity_checks();
    for count in [1, 2] {
        let prefix = snapshot.run(first, count).unwrap();
        assert_eq!(prefix.len(), count as usize * PAGE_SIZE);
        assert!(!verify_run(first, prefix));
    }
    snapshot.page(first).unwrap();
    assert_eq!(scratch.pager().integrity_checks(), checks);
    assert_eq!(scratch.pager().run(first, 1).unwrap_err().kind(), ErrorKind::Damaged);
}
```

**Evidence type:** executed reproduction and source argument. The page numbers collide by the table's modulo indexing. Snapshot reads select `UseRemembered` (`scratch.rs:1092–1098`), so the optional length check is reached through the existing snapshot API. The original regression test only checks incorrect extents while the mark remains present; the new eviction test checks correct extents only. Neither combines their conditions.

**Requirement:** I1/I2 and the inherited complete-run integrity contract, associated with S1/AC-I1 and V7. I1 states: “Un valor guardado fuera de su hoja, que se comprueba entero, se recuerda y se olvida entero.” `Snapshot::run` explicitly promises damage when the pages are not one run of exactly `count` pages (`scratch.rs:1033–1037`); `ReadTransaction::run` propagates that contract (`transaction.rs:68–77`). `format::verify_run` binds integrity to the exact supplied extent (`format.rs:280–286`).

**Assessment of the recorded residual:** the resolutions and ODD L13/L14 correctly acknowledge the behavior, but do not establish an approved exception to these contracts. I8 accepts external changes to already-remembered bytes; this reproduction changes no bytes. Acknowledging an invalid reference does not verify that the promised damage check remains intact.

**Impact boundary:** a demonstrated internal integrity-contract regression, at a realistic store size slightly above 512 MiB. No incorrect result through valid operations of the top-level `Store` facade, durability failure or memory unsafety was demonstrated. Severity remains major, as in the original R1.

**Suggestion:** preserve exact run identity independently of replaceable node-table entries, and combine eviction with invalid-extent and standalone-head regression tests.
