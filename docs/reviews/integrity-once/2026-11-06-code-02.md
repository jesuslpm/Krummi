## Open findings introduced by the corrections

<a id="R3"></a>
### R3 — major — Shared table eviction makes unchanged values repeat integrity checks

**Location:** `crates/krummi-pager/src/pager.rs:418–434`; `crates/krummi-pager/src/checked.rs:91–103,117–119`.

A multi-page value now requires a mark in the fixed, replaceable node-layout table to skip its checksum. Remembering another run or a checked node in the same slot overwrites that mark. The original bitmap representation retained the value until a write or close; the replacement can forget an unchanged value solely because unrelated data was read. Alternating colliding values therefore recalculates their complete checksums on every access indefinitely.

**Executed reproduction:** using the default `CHECKED_SLOTS == 65536`, create two valid three-page runs at pages `6` and `65542` in a temporary pager, write both, and read both with `UseRemembered`. They share a table slot. Reading the second makes `is_run_remembered(6, 3)` false. Six subsequent alternating reads add exactly six integrity checks, despite no intervening writes, growth or reopen. No checksum collision, damaged data or disabled measurement switch is involved.

An additional executable reproduction exercised ordinary tree operations with the existing `with_checked_slots(1)` test hook: create a tree and one three-page value through `krummi_tree::set`, commit, call `Engine::transfer_now`, and read the value. Three subsequent `krummi_tree::get` calls return the correct value but add three integrity checks. The leaf's layout check replaces the run mark on each descent (`crates/krummi-tree/src/lib.rs:249–253`), so even the same value can repeatedly lose its integrity memory. The reduced table makes the same slot replacement compact; the default-size pager reproduction independently confirms it without changing table size.

**Evidence type:** executed reproductions plus the source causal chain above. Both stdin-compiled harnesses exited 0 after asserting the unexpected check counts. The default-size scenario is a store slightly larger than 512 MiB, within the supported temporary-store reservation and a realistic disk-store size.

**Requirement:** S1/AC-I1: “la integridad de cada página y del valor se comprueba solo en su primera lectura”; I1/I2 and the per-opening lifetime also apply. C5 explicitly permits eviction of remembered node **organization**, not eviction of remembered value **integrity**. ODD L12 acknowledges the repeated checks as an advisory that “only costs time”; this does not establish an exception to the product contract. The resolutions' claimed exact-extent fix is confirmed, but this associated disposition is unsupported by the stated requirements.

**Impact boundary:** a demonstrated substantive requirement and performance-behavior regression; the reproductions returned correct data. No benchmark slowdown magnitude or data corruption is claimed.

**Suggestion:** preserve remembered run integrity independently of node-table replacement and test competing value and node slots.

**Status:** open; introduced by `e5ea5362863645f4af355bc0dccbdc903c6de9d6`.

<a id="R4"></a>
### R4 — minor — Rewriting only a run's head does not reliably invalidate it

**Location:** `crates/krummi-pager/src/pager.rs:418–421,616`.

The fast path now consults only interior-page bits and the head's stored-checksum/length mark. The write path still invalidates only bitmap bits. A write covering the head alone clears a bit the fast path no longer uses, leaving the entire run remembered whenever the stored checksum remains unchanged. The comment that a rewritten first page has another stored code is insufficient: rewriting identical bytes preserves it.

**Executed reproduction:** remember a valid three-page run, then pass its original first-page fragment to the pager write wrapper, which calls `write_run_shared`. That helper explicitly supports pages of a run (`pager.rs:591–593`). Afterwards, `is_run_remembered(first, 3)` remains true and `run_with(first, 3, UseRemembered)` adds zero integrity checks. The pre-fix bitmap fast path required the head bit too, so the same write invalidated it. The added test changes and reseals the first page instead (`pager_tests.rs:691–700`); the resulting different checksum masks the missing invalidation.

**Evidence type:** executed reproduction and source argument. The harness exited 0 after asserting the stale remembered state and unchanged check counter. This establishes the internal fragment-write invariant; it does not claim that a run prefix is a standalone sealed run under the narrower `write_run` documentation.

**Requirement:** I4: “esa página deja de estar recordada antes de escribirla, y con ella el valor fuera de su hoja que la contenga entero. La primera lectura posterior la comprueba otra vez.” No dedicated acceptance criterion exercises an identical head-only rewrite; S4/AC-I4 covers the corresponding rewrite-invalidates rule through the product facade.

**Impact boundary:** limited internal invalidation defect. The ordinary transfer writes a run's complete slot (`scratch.rs:679`); `flush_all` writes its pages individually only during close, without snapshots (`scratch.rs:743–759`), and reopening starts with empty memory. No wrong result or memory-safety failure through valid `Store` operations was demonstrated. Malformed writes with an intentionally stale checksum are not used to elevate severity.

**Suggestion:** invalidate the head's run memory before writing it and cover an identical head-fragment rewrite.

**Status:** open; introduced by `e5ea5362863645f4af355bc0dccbdc903c6de9d6`.
