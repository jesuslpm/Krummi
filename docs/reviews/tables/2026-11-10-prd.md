## Findings

<a id="R1"></a>
### R1 — Failed-load statistics criterion assumes whole-load atomicity

- Severity: **major**.
- Location: Acceptance criteria / AC-N8, docs/prd/krummi/tables.prd.md:251; child allocation / 7.1, line 91; AC-N3, line 197.
- Status: **open**.

AC-N8 unconditionally requires: “cuando una carga masiva falla mientras se construyen estadísticas en segundo plano, entonces las que se guardan no cuentan ninguna fila de la carga”. However, 7.1 is expressly responsible for deciding “si una fila con una clave repetida o un valor no válido hace fallar la carga entera sin efecto o solo esa fila” and “si cabe en una sola escritura”. AC-N3 correctly makes complete rollback conditional: “si 7.1 fija que la carga falla entera”. AC-N8 omits that condition.

The allowed readings produce different observable outcomes:

- With a wholly atomic load, no load rows become committed after failure, so a background snapshot must not sample any of them.
- If 7.1 allows committed batches before a later failure, a background snapshot may legitimately sample those earlier committed rows. For example, the first batch commits, sampling starts, and the next batch or input source fails. The unconditional AC-N8 assertion requires excluding even the committed first batch.

This is a conflict between an acceptance criterion and an expressly delegated policy, rather than a finding that 7.1 must decide its policy now. The design corroborates the hidden assumption: docs/design/tables/03-keys-and-indexes.md:458 explains the exclusion with “the load's rows were never committed, so no snapshot sees them”. That rationale depends on whole-load rollback, which this umbrella has not required. Statistics being approximate does not settle which committed state this failure test is allowed to sample.

Suggestion: condition complete exclusion on whole-load atomicity, and make other cases follow the committed-row semantics chosen by 7.1.
