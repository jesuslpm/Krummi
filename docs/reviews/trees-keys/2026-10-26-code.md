## New finding

<a id="R3"></a>
### R3 — major: rename reserves a name before rejecting an existing destination

- Location: `crates/krummi/src/lib.rs:345`, particularly `copy_str` at line 346, before destination lookup and
  rejection at lines 349–351. Introduced by the R1 fix, `06ec986`.
- Requirements: A3/A6, A7, B7; AC-A13 / S13. A7 prioritizes "los fallos al leer el catálogo (daño, memoria
  agotada, entrada y salida)" before the public validation errors. The new allocation copies an argument
  for the open-tree table; it is not a failure reading the catalog. A rename to an existing destination
  without overwrite must report `TreeAlreadyExists`, a public validation failure that does not invalidate
  the transaction.
- Concrete scenario: trees `t` and `u` exist; a write opens `t` and changes `k` from `before` to `changed`.
  The application calls `rename_tree("t", "u", false)` while the next tree-memory reservation fails.
- Causal chain: because `t` is open, the method first calls `copy_str(to)` to prepare its new table name.
  That unnecessary allocation fails before it checks that `u` already exists. `reserve` routes the error
  through `fail`/`track`, so the method returns `OutOfMemory` and the transaction records a T11 failure.
  A subsequent commit fails with `OutOfMemory`, leaving the previously committed `before` value intact
  instead of committing `changed`. The transaction should have remained committable after the rejected rename.
- Evidence: source comparison with the original reviewed commit, where destination validation preceded
  name copying, and a successful isolated reproduction using the engine's `Op::Alloc` fault hook (below).
  The fault counters were reset immediately before injection. Both rename and commit returned
  `OutOfMemory { requested: 1 }`; a new read observed `before`. This is demonstrated, not hypothetical.
- Existing regression tests exercise allocation failure while renaming to an absent destination; they do
  not exercise allocation refusal before a destination-already-exists rejection.
- Impact: wrong error precedence and unnecessary loss of the ability to commit pending changes, not
  corruption of already-committed data. No memory-unsafety or durability failure was demonstrated.
- Suggestion: validate the destination first, then reserve the replacement name before making any changes.

## R3 reproduction

Compiled from standard input to `target/review-rename-probe.exe`, linked to the current `krummi` and
`krummi-pager` debug libraries with test hooks and `-L dependency=target/debug/deps`. No source file was
created or modified. All store data is in memory.

```rust
use krummi::{ErrorKind, OpenMode, Store, StoreOptions, TreeKind};
use krummi_pager::testing::{self, Action, Op};
fn main() {
    let store = Store::open_temporary(&StoreOptions::default()).unwrap();
    let mut write = store.write().unwrap();
    let t = write.open_tree_with("t", TreeKind::Normal, OpenMode::CreateNew).unwrap();
    write.set(&t, b"k", b"before").unwrap();
    write.open_tree_with("u", TreeKind::Normal, OpenMode::CreateNew).unwrap();
    write.commit().unwrap();
    let mut write = store.write().unwrap();
    let t = write.open_tree("t", TreeKind::Normal).unwrap();
    write.set(&t, b"k", b"changed").unwrap();
    testing::reset();
    testing::inject(Op::Alloc, 0, Action::Fail(std::io::ErrorKind::OutOfMemory));
    let rename = write.rename_tree("t", "u", false);
    testing::reset();
    eprintln!("rename result: {rename:?}");
    let commit = write.commit();
    eprintln!("commit result: {commit:?}");
    let read = store.read().unwrap();
    let t = read.open_tree("t", TreeKind::Normal).unwrap();
    eprintln!("persisted value: {:?}", read.get(&t, b"k").unwrap());
    assert_eq!(rename.unwrap_err().kind(), ErrorKind::OutOfMemory);
    assert_eq!(commit.unwrap_err().kind(), ErrorKind::OutOfMemory);
    assert_eq!(read.get(&t, b"k").unwrap(), Some(&b"before"[..]));
}
```

Observed output:

```text
rename result: Err(OutOfMemory { requested: 1 })
commit result: Err(OutOfMemory { requested: 1 })
persisted value: Some([98, 101, 102, 111, 114, 101])
probe exit code: 0
```
