<a id="R1"></a>
### R1 — Major: sampling skips compression of strongly compressible records

**Location:** `crates/krummi-pager/src/journal.rs:357–363`, with the eligibility decision at `:396–408`.

For payloads of at least 4 MiB, each probe compresses an independent 32 KiB sample. A large value made by repeating a pseudo-random 48 KiB block has no repeated block within any sample, although a complete LZ4 compression can exploit that repetition. The probe returns false and `encode_record_in` stores the whole payload raw. This is a substantial false negative, not merely forfeiting a negligible saving.

**Evidence: executed isolated reproduction plus source-level causal argument.** The coordinator constructed a valid, sealed 520-page value run starting at page 100, verified it with `format::verify_run`, and encoded its raw-page entries in the format used by `encode_page`. Using the repository's built `lz4_flex`, the observed result was:

```text
valid_sealed_run=true raw=4267120 sample_lengths=[32898, 32898, 32898, 32898, 32898, 32898, 32898, 32898] sample_total=263184 probe_accepts=false whole_compressed=135568 raw_over_compressed=31.48
```

Such a value is reachable through the supported large-value interface. Samples miss the repetition, so lines 357–360 omit full compression and lines 361–363 select 4,267,120 raw bytes instead of the 135,568-byte compressed representation. This increases journal record bytes and write traffic by about 31 times in this probe. It does not imply that a preallocated journal file's physical size immediately grows by the same factor. Recovery still accepts the raw representation; no recovered-data difference is claimed. The probe isolates encoding/compression rather than running a complete `Store` transaction.

**Requirement:** S2 retains J16; `docs/prd/krummi/journal/journal-page-diffs.prd.md:42`, Y1, states: «Después se comprime como hoy cuando ocupa menos comprimido». J16 also promises smaller journal storage when data compresses well. Implementation freedom over the algorithm does not declare an exception allowing strongly compressible records to be stored raw. L4 acknowledges false negatives but does not resolve this requirement discrepancy. The new positive compression tests do not exercise repetitions longer than a sample.

**Suggestion:** Preserve J16/Y1 for compressible records and add a regression case whose repetition distance exceeds the sample length.

<a id="R2"></a>
### R2 — Major: Q3 metadata adds an allocation that can fail during commit

**Location:** `crates/krummi-tx/src/transaction.rs:604`.

Every commit with dirty pages constructs a separate `Vec<bool>` containing the retained-layout flags. This allocation is new relative to the base, happens even when every flag is false, and occurs after `finish_space` while the page buffers remain live. A memory-constrained commit can therefore fail solely while allocating the additional bookkeeping. `collect()` does not return the engine's `OutOfMemory` error; allocation failure takes the allocator failure path instead.

**Evidence: source-level technical argument; allocator exhaustion was not induced.** The new vector is unconditionally collected from the nonempty dirty map before `stage`/journal enqueue. Its contents exist only to transport Q3 metadata to `ScratchWriter::commit`. This finding concerns that introduced allocation, not the pre-existing page/created vectors or other pre-existing collections. Debug builds additionally insert retained-layout provenance into a growing `HashMap` at `pager.rs:410`, after the page write in `scratch.rs:813–819`; the release-visible vector alone establishes the discrepancy.

**Requirement:** S1/Q6, `docs/prd/krummi/pager/pager-written-pages.prd.md:43`: «Lo que recuerdan Q1 a Q3 usa las memorias que ya existen (I6, C5, U1) y no reserva memoria que pueda faltar». This is an explicit constraint on the new bookkeeping, rather than a general demand to remove every existing allocation from the engine.

**Suggestion:** Carry the retained-check flag through already-reserved metadata without an additional allocation during commit.

### R4 — Minor: debug cache lookups add blocking synchronization between readers

**Location:** `crates/krummi-pager/src/pager.rs:371–378`, called from `crates/krummi-tree/src/lib.rs:310`.

In debug builds, every node read that hits C2 calls `layout_kept` and locks the same `kept_layouts` mutex, including ordinary nodes that never retained a Q3 check. Two readers of an already-warmed persisted root can therefore block on one another's new provenance lookup; the transfer also takes that mutex when updating provenance at `pager.rs:405–410`.

**Evidence: direct call-chain and mutual-exclusion argument.** The cache-hit branch unconditionally evaluates `layout_kept` when debug assertions are enabled. Its `.lock()` introduces shared blocking synchronization that was absent at the base. No deadlock or release-build impact is claimed.

**Requirement:** S1 inherits C6 of `docs/prd/krummi/trees/trees-node-check-cache.prd.md:48`: «consultar y añadir recuerdos no añade esperas bloqueantes entre lecturas ni con la escritura». The Q4 debug checks and the new annotations do not declare an exception. L4 notes the mutex as an advisory but does not settle the contract discrepancy. Impact is limited to debug builds, hence minor severity.

**Suggestion:** Track debug provenance without adding a shared blocking lock to remembered-node reads.

## Reproducing R1's sealed-run probe

The following is equivalent standalone source for the probe passed to `rustc` through stdin, linking the already-built `lz4_flex` and `krummi_pager` dependencies with `-L dependency=target/debug/deps`; the executable was `target/review_compression_sealed_probe.exe`. It creates no store or source file. The encoding is the single-full-page-run case of `encode_page`.

```rust
fn main() {
    let mut x = 0x2545_F491_4F6C_DD1Du64;
    let block: Vec<u8> = (0..48 * 1024).map(|_| {
        x ^= x << 13;
        x ^= x >> 7;
        x ^= x << 17;
        x as u8
    }).collect();
    let mut run: Vec<u8> = (0..520 * 8192)
        .map(|i| block[i % block.len()]).collect();
    krummi_pager::format::seal_run(100, &mut run);
    assert!(krummi_pager::format::verify_run(100, &run));
    let mut raw = Vec::new();
    for (page, bytes) in run.chunks_exact(8192).enumerate() {
        raw.extend_from_slice(&((page as u64 + 100) | (3u64 << 62)).to_le_bytes());
        raw.extend_from_slice(&1u16.to_le_bytes());
        raw.extend_from_slice(&0u16.to_le_bytes());
        raw.extend_from_slice(&8192u16.to_le_bytes());
        raw.extend_from_slice(bytes);
    }
    let part = raw.len() / 8;
    let lengths: Vec<usize> = (0..8).map(|i| {
        let at = i * part + (part - 32768) / 2;
        lz4_flex::block::compress(&raw[at..at + 32768]).len()
    }).collect();
    let sampled: usize = lengths.iter().sum();
    let whole = lz4_flex::block::compress(&raw);
    assert!(sampled + 262144 / 32 > 262144);
    assert!(whole.len() < raw.len() / 10);
    println!("raw={} samples={lengths:?} compressed={}", raw.len(), whole.len());
}
```
