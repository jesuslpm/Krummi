## Findings

<a id="R1"></a>
### R1 — major — Checkout cleanup retains untracked nested Git repositories

- **Location:** `scripts/runner/runner.sh:63`.
- **Problem:** `git clean -qfdx` removes ordinary untracked files but protects nested Git repositories. The checkout therefore is not reset to just the requested commit between runs.
- **Concrete failure:** a `run` task clones or initializes a dependency under the checkout. A subsequent task, potentially targeting another commit, still sees that untracked dependency and can compile, test, or benchmark against stale inputs from the previous task.
- **Evidence — experimental reproduction:** in an isolated local runner home, a first task ran `git init -q stale-dependency; printf 'stale\n' > stale-dependency/file`. A later invocation of the unmodified runner checked `stale-dependency/file` and printed `STALE_REPOSITORY_SURVIVED`. The coordinator independently repeated the second invocation and observed the same output after the normal fetch, checkout, and cleanup. Existing cleanup coverage tests only an ordinary untracked file.
- **Violated contract:** `docs/linux-runner.md:44`, “the checkout is wiped before each run”; the disposable-checkout description at `scripts/runner/runner.sh:15-17`. No S#/AC applies.
- **Causality:** introduced by this range; the runner does not exist at the base.
- **Suggestion:** remove nested untracked repositories as part of cleanup, strictly within the disposable checkout.
- **Status:** open.

<a id="R2"></a>
### R2 — minor — Concurrent first calls race during shared repository initialization

- **Location:** `scripts/runner/runner.sh:27-29`; caller failure propagation at `scripts/runner/Invoke-Linux.ps1:50-51`.
- **Problem:** the existence check and `git init --bare` execute before acquiring `flock` at lines 52-53, and the `init` path exits without acquiring it at all.
- **Concrete failure:** two initial invocations reach a fresh runner home together. Both observe no `repo.git` and initialize the same directory. Git collides while creating configuration or template files; `Assert-Success 'runner.sh init'` aborts an invocation before its task runs, rather than safely serializing initialization or reporting the documented busy status.
- **Evidence — experimental reproduction:** the critical reviewer ran 150 pairs of unmodified `runner.sh init` invocations against fresh disposable homes with real local Git and observed 98 exits with status 128. An example reported `could not lock config file .../repo.git/config: File exists` followed by `fatal: could not set 'core.bare' to 'true'`. The coordinator independently reproduced the race in the second pair of a bounded 30-pair probe, receiving `fatal: cannot copy '/usr/share/git-core/templates/description' to '.../repo.git/description': File exists` and `init_exit=128`.
- **Violated contract:** shared-runner serialization and busy handling in `docs/linux-runner.md:46-47`. No S#/AC applies.
- **Impact:** retryable cold-start failure. No corruption or data loss was demonstrated; this is not a critical storage defect.
- **Causality:** introduced by this range; the shared initialization is new.
- **Suggestion:** protect repository initialization and its readiness check with mutual exclusion.
- **Status:** open.
