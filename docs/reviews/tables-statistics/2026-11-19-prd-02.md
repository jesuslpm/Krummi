## Verification of original findings

<a id="R1"></a>
### R1 — verified resolved — Analyze publication after failure

Original: [2026-11-19-prd.md#R1](2026-11-19-prd.md#R1), originally **blocker**.

ST7 now explicitly says: “Si falla después de muestrear (al esperar el turno o al guardar), lo publicado se queda en memoria”. AC-ST9 replaces the incompatible no-effects assertion with unchanged stored state and an explicit exception for shared publication (`docs/prd/krummi/tables/tables-statistics.prd.md:56`, `:255–259`).

Rechecked original counterexample: another thread holds the write turn, a populated table has no statistics, and store-level analyze uses a zero wait limit. The revised contract consistently requires sampling and publication, a timeout obtaining the write turn, retained statistics in shared memory, and a later estimate using them without resampling. ST7/ST9 cover retrying their save, subject to ST6's prohibition on work when T12 has disabled writes. No rollback of an already observed publication is required. Stored data, writer-private analyze/abort behavior and the existing write-turn rules remain distinct and consistent.

<a id="R2"></a>
### R2 — verified resolved — Estimate value-size limits

Original: [2026-11-19-prd.md#R2](2026-11-19-prd.md#R2), originally **major**.

ST2 now states: “A diferencia de IX9, los valores no tienen límite de tamaño: se acepta cualquier valor válido para su columna (E18), y ninguna estimación falla con tamaño no válido por sus valores.” ST18 applies ST2 to each value in a multi-column equality (`tables-statistics.prd.md:51`, `:67`).

The original 4,096-byte equality on an unindexed column therefore has a defined result rather than an unresolved encoded-prefix-size error. ST1 defines large string/byte values as over 2,048 bytes; ST2 defines their contributions to equality and intervals, with its exact rules still applying afterward. ST16 exposes the large-value fraction, and AC-ST12 checks the 2,048/2,049 boundary and a 4,096-byte equality (`:50–51`, `:65`, `:271–274`). Multi-column inputs no longer inherit a combined encoded-prefix cap or an undefined index-specific error payload.

The new no-payload-page-read requirement was also traced through row storage and integrity; see the regression sweep below. It is an implementation obligation, not evidence that the original size-limit ambiguity remains open.

The coordinator checked the retained conclusions against the cited documents and source.

No additional unresolved product interpretation was demonstrated.

A possible large-value regression was investigated and **not retained as a finding**. Current rows are whole tree values (`crates/krummi/src/table/row.rs:1–17`); sufficiently small rows containing 2,049-byte payloads can still be inline (`crates/krummi-tree/src/node.rs:31–62`). Off-leaf rows resolve the entire value run (`krummi-tree/src/lib.rs:350–361`), whose checksum covers that run (`crates/krummi-pager/src/format.rs:17–20`; `pager.rs:431–448`). Thus merely skipping value decoding in the existing scan would not establish AC-ST12's page-read assertion, especially after reopening without remembered integrity checks.

That limitation does not establish a contradiction in an unimplemented PRD: the parent expressly leaves row encoding and tree organization to implementation (`tables.prd.md:361–364`). A separate trusted metadata/access path could avoid reading payload runs while preserving inherited integrity guarantees. This review neither selects that design nor authorizes bypassing integrity checks. The future implementation must demonstrate both the page-read criterion and the inherited integrity contract; no such implementation or runtime success is claimed here.
