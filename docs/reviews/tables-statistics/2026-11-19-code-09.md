### R13 — Major: Reachable failure phases still lack acceptance coverage

- Status: **still open, partially corrected** by `da56d24`.
- Locations: `crates/krummi/src/table/stats_fault_tests.rs:82`, `:158`, `:216`; `crates/krummi/tests/table_statistics/codex.rs:612`, `:742`. Dependencies: `crates/krummi/src/table/statistics.rs:649`, `:787`-`:815`.
- **Coverage evidence:** inventory of all statistics tests, prior reports and resolutions. The new commit-I/O unit tests now call `Engine::checkpoint` before injecting write failures. Unlike `make_durable`, checkpoint waits for the transfer (`krummi-pager/src/scratch.rs:634`-`:646`); this closes the prior isolation defect. The new deterministic store-analyze damage test also closes that specific omission. The commit cases cover retained memory, write refusal and, for the background case, close/reopen.
- A concrete still-uncovered phase is **OOM after publication**: create a committed nonempty table without statistics, then call `Store::analyze` with `Op::Snapshot` failure number 1. The read snapshot succeeds, sampling publishes statistics, and acquisition of the internal write snapshot fails. ST7 requires `OutOfMemory`, retained memory statistics, continued writes, and a later estimate saving those statistics. The existing OOM test fails snapshot number 0 and asserts that nothing was published; it cannot cover this opposite state. Save-page OOM also has no statistics-specific test, although the existing page-fault hook supports it. There is likewise no failure-injection test of `WriteTransaction::analyze` asserting T11 and preservation of earlier committed state; the existing write-damage test calls `estimate`.
- **Independent runtime verification:** the coordinator injected snapshot OOM number 1 through the public analyze path. Two snapshot attempts occurred; analyze reported `OutOfMemory`, statistics remained in memory, another write succeeded, and a later estimate saved them without another sample; reopen retained them. A separate disposable-store probe damaged the table leaf, made an unrelated change in a write and called that write's `analyze`: analyze and commit both returned `Damaged`, and the next write succeeded. These checks passed; they establish no runtime defect. Disposable review probes do not supply the missing repository acceptance cases.
- **Correction to the preceding review's assessment:** the stated mapped-page read-I/O limitation is valid. P17 (`docs/prd/krummi/pager/pager.prd.md:45`) and the root's G12 exception (`krummi.prd.md:178`-`:180`) permit a physical mapped-read failure to terminate the process. `Op::Read` targets journal reads; `Op::Snapshot` converts an injected failure into OOM (`scratch.rs:693`-`:697`). A requirement for a safe `Io` return from a physical mapped-page read is therefore withdrawn. Damage is still a distinct error class, but that distinction does not make the excluded physical-read test mandatory. The remaining finding relies only on reachable phases above.
- Requirements: S1/S4, ST7/ST9 and AC-ST8; ST7: «Si falla después de muestrear (al esperar el turno o al guardar), lo publicado se queda en memoria» and «sus fallos siguen los de cualquier operación de una escritura (T11)».
- Suggestion: add permanent tests for reachable post-sampling allocation/save failures and write-analyze failure effects.
