<a id="R2"></a>
### R2 — Blocker: Sampling still reads entire runs containing large values

- Status: **still open**, explicitly pending in the resolutions and ODD T7b; no partial-run implementation was supplied.
- Locations: `crates/krummi/src/table/statistics.rs:491`, `:508`, `:628`; `crates/krummi-tree/src/lib.rs:613`, `:361`.
- **Verifiable technical evidence:** whole-table scans and random-leaf sampling resolve complete rows before gathering. The shared resolver calls `tx.run(first, count)` for an external value, reading/verifying the entire run. `Gather::add` classifies a large column only afterwards (`stats.rs:141`). A valid row with a small estimable column and a multi-MiB blob therefore still requires reading the blob when estimating the small column; damage in pages that sampling must skip can still fail that estimate. The original reproduction and both follow-ups' causal analysis remain applicable to the unchanged resolver, including write sampling.
- Requirement: S1/ST1: «Los **valores grandes** […] no se leen» and «sin verificar la suma de comprobación del tramo entero»; ST14/AC-ST12's page-read verification remains absent.
- Suggestion: complete partial run/row reads and assert which pages sampling actually reads.

<a id="R11"></a>
### R11 — Major: Removed targets can still be republished from old snapshots

- Status: **still open, partially corrected**. One mutex now makes epoch validation and insertion atomic against retirement; retiring before releasing the writer also closes the previously reported later-writer window. Neither correction establishes target/snapshot validity at publication.
- Locations: `crates/krummi/src/table/estimate.rs:126`, `:141`; `crates/krummi/src/table/statistics.rs:476`.
- Failure: retiring a removed column/index deletes its current entries without recording the removed identity or changing the table epoch. `publish` subsequently accepts that target again. Independently, an old read starting a build after retirement captures the current memory epoch despite reading its old schema and rows. Saving filters nonexistent targets, but shared publication does not.
- **Independent experimental evidence, reproducing round 3:** commit three rows in `t(id,n)` with `ix(n,id)`, without saved statistics. Open read A and its table. Drop `ix` and `n` in another write and commit. A initially has no column statistics. Estimate `n = 1` through A, then wait for statistics work to become idle. A obtains `Some(origin_rows=3)` column statistics and prefix statistics. Its snapshot predates every saved statistic, proving the removed entries were reintroduced in memory.
- **Second independent reproduction:** hold store analyze at `WorkSampled`, remove the same index/column and commit, then release analyze. The old read again obtains both removed targets from memory. This is AC-ST6's paused-build case; the latest removal-only retirement makes the build's unchanged table epoch pass.
- Requirement: S1/ST1/ST6/ST8/AC-ST6: «cuando se quita la columna, entonces no se publican ni se guardan para ella». Old snapshots retaining their own saved data do not authorize reintroducing removed shared entries.
- Suggestion: validate the source snapshot and each target's committed lifetime when publishing and saving.

### R12 — Major: Cancellation still completes all gather finalization

- Status: **still open, partially corrected**. The new post-iteration check fixes cancellation observed by `take_while`; the finalization subcase explicitly recorded in round 3 remains.
- Locations: `crates/krummi/src/table/statistics.rs:198`, `:210`, `:219`; `crates/krummi/src/table/stats.rs:153`.
- **Verifiable technical evidence:** after the single check at line 198, construction unconditionally finalizes every column and index-prefix gather. `Gather::finish` sorts the values, groups runs, selects frequent values and constructs a histogram, without receiving/checking cancellation; `finish_combinations` invokes the same work. If shutdown begins during the first finalization, all remaining gathers still finish before `worker::renew` checks stopping and drops the result. `Work::stop` joins that worker, so close waits for this avoidable construction.

- Requirement: S1/ST10: «cerrar detiene el muestreo en curso del hilo sin publicarlo ni guardarlo»; AC-ST7.

<a id="R18"></a>
### R18 — Major: A failed commit retires statistics for changes it never applied

- Status: **new regression**, introduced by moving retirement before `inner.commit`/`commit_deferred` in `8f7f4e4`.
- Locations: `crates/krummi/src/lib.rs:1593`, `:1605`; retirement at `crates/krummi/src/table/estimate.rs:126`.
- Failure: retirement now deletes entries and advances epochs while commit can still fail before applying any change. There is no restoration. Dependencies `krummi-tx/src/transaction.rs:608`, `:624` and `krummi-pager/src/scratch.rs:1471`, `:1572` establish fallible preparation/staging before publication. The resolutions' statement that a failed commit merely causes resampling describes the effect but does not satisfy retirement only for confirmed changes.
- **Independent experimental evidence:** create and commit one row in `t(id,n)`. Open read A before store analyze, so A sees the analyzed statistics only through memory. In another write empty `t`, create normal tree `large`, and set a 2 MiB value. Immediately before commit, reset fault counters and inject `Op::Alloc`, future call 1, as `OutOfMemory`. Both durable and deferred variants return `OutOfMemory`; a new read still sees the original row and no `large` tree, proving neither change applied. Nevertheless A's `column_statistics("n")` changes from `Some` to `None`. The statistics were retired by the aborted lifecycle change.
- Control sweep: failure at allocation 0 leaves the original row and memory statistic intact; with no fault reached at positions 2 through 5, commit succeeds, leaves zero rows, and correctly retires memory. This distinguishes the new commit-ordering path from an earlier preparation failure.
- Requirement: S1/ST1/ST8: memory statistics end «en el momento en que se confirma ese cambio». Here the emptying never committed. This affects statistic visibility and unnecessary rebuilding, not demonstrated loss of persisted rows.
- Suggestion: coordinate retirement with effective commit publication while preserving writer ordering and failure rollback semantics.

<a id="R19"></a>
### R19 — Minor: Every commit scans all shared statistics even with nothing to retire

- Status: **new regression**, introduced by the replacement of `retire` in `8f7f4e4`.
- Locations: `crates/krummi/src/table/estimate.rs:126`, `:131`, `:134`; unconditional callers `crates/krummi/src/lib.rs:1593`, `:1605`.
- **Verifiable technical evidence:** the base returns immediately for an empty retirement list. The new method takes the shared mutex and calls `retain` on both complete entry maps even when all three retirement lists are empty. An ordinary write to a normal tree, or an unchanged commit, supplies exactly that empty `Retired` through `finish_tables`. It now traverses the global column and prefix registries while keeping the write turn and mutex, although all entries are retained. Work formerly constant for this case grows with unrelated stored statistics, and statistics readers/publications share that mutex.
- This is a source-established complexity regression; no measured latency or benchmark result is asserted.
- Requirement: engineering principles, performance by design and avoiding unnecessary work in shared write paths.
- Suggestion: return immediately when all retirement lists are empty.
