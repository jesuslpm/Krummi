### R2 — Minor: Sampling page counter omits metadata pages actually read

- Status: **still open, partially corrected** by `a1946cf`. The hook and its narrow-row acceptance test now exist; the hook does not correctly count all run-page accesses.
- Locations: `crates/krummi/src/table/statistics.rs:203`, `:211`, `:234`; `crates/krummi/src/table/rows.rs:1043`. Dependencies: `crates/krummi/src/table/row.rs:185`-`:222`, `:640`-`:652`.
- **Concrete valid-input reproduction:** create a table with `id i64 NOT NULL PRIMARY KEY`, 600 nullable `Ulid` columns, `big bytes NOT NULL`, and `tail string NOT NULL`. Insert one row with `id=1`, all 600 fixed columns null, `big` containing 200,000 bytes, and `tail="tail"`. Call `Store::analyze("t", Some("big"))` and measure the delta of `statistics_pages_read()`.
- **Independent runtime result:** the delta is **1**, while analysis succeeds with `rows_read=1` and `large_fraction=1`. A probe using the public `RowLayout` encoder confirms that the first variable end offset is at row byte **9,678**, or run byte **9,694**, on run page **1** (8,192-byte pages and a 16-byte run header). This is a runtime reproduction of the incorrect counter combined with the source-level access argument below, not an operating-system page-fault trace.
- **Causal evidence:** fixed slots occupy space even when their values are null. The end offsets follow those slots. `stored_len -> stored_slice -> Row::column_bytes -> Row::variable` reads `big`'s end offset from page 1 to classify it as large. The row header is read from page 0. Because the value is large, `build` skips `touch`; it then adds only page 0. The two required metadata pages are therefore reported as one. `run_pages` describes column payload ranges and does not record the metadata accesses made to find them. The new four-column test keeps all metadata on page 0 and cannot detect this omission.
- The hook computes selected ranges beside decoding rather than observing all accesses in the decoder/resolver. Additional payload accesses introduced inside those dependencies could also evade the counter. No claim is made that the current sampler actually reads the skipped large payload or checksums the whole run.
- **Prior runtime defect rechecked:** independently repeated the exact offset-only corruption reproduction from rounds 7-9 against the head libraries. For `t(id i64 PRIMARY KEY, s string NOT NULL, blob bytes NOT NULL)` with `(1, "x", 200,000 bytes)`, replace the first variable end offset at `first_page * 8192 + 16 + 3` with little-endian `u32::MAX`, leaving the header intact. Analyze succeeds without an escaping panic; all columns report `rows_read=1`, with large fractions `id=0`, `s=1`, `blob=1`. Ordinary `get_row` still returns `Damaged`. The earlier malformed-offset and whole-run integrity defects are not asserted to remain.
- Requirements: S1/ST14, «otro cuenta las páginas que lee un muestreo»; AC-ST12, «el gancho de pruebas que cuenta las páginas leídas muestra que el muestreo no lee las páginas de esos valores».
- Suggestion: count effective sampling accesses, including offset/header pages, and add an assertion with offsets beyond the first page.
