### R2 — Blocker: Partial-run sampling can panic on corrupt offsets

- Status: **still open, partially corrected** by `91111a3`. The original whole-run checksum/read problem is addressed in the new resolver, but its replacement does not implement ST1's mandatory bounded, non-panicking sampling. This is the same unfinished partial-run requirement, retaining R2.
- Locations: `crates/krummi/src/table/statistics.rs:200`, `:207`, `:423`; `crates/krummi/src/table/rows.rs:719`, `:729`; dependency `crates/krummi/src/table/row.rs:617`.
- Failure scenario: a row in a run has two variable columns and an end offset outside the run. Sampling now bypasses the run checksum and decodes with `check = false`. `stored_len` turns the invalid offset's `RowDamaged` into `None`; the gatherer treats that as a value that is not large and calls `row.value`. That reaches the ordinary unchecked row decoder, whose malformed-column branch panics. The shared builder is used by estimates and analyze, including background renewal.
- **Independent experimental evidence:** create and durably close a disposable store with `t(id i64 PRIMARY KEY, s string NOT NULL, blob bytes NOT NULL)`, one row `(1, "x", 200,000 bytes)`. Its stored header is `[1, 0, 2, 1, 0, 0, 0, 120]` and its run has 25 pages. Through an offline file write, replace the first variable end offset at `first_page * 8192 + 16 + 3` with little-endian `u32::MAX`, without recomputing integrity. Reopen and call public `Store::analyze("t", None)`. A surrounding `catch_unwind` records `analyze panicked=true`, with `a malformed row: a column that does not decode` at `row.rs:617`. An ordinary public `get_row` still returns `ErrorKind::Damaged`. The probe exits 0 after asserting both outcomes. Previously, the checked run resolver rejected this altered run before the malformed decoder.
- Requirement: S1/ST1: «los límites se comprueban, así que un tramo dañado nunca termina en un pánico, y un desplazamiento fuera del tramo cuenta como valor grande». The supplied correction does neither for this reproduced offset.
- **Resolution evidence assessed:** `Integrity::Unchecked`, borrowed run slices and length-based large-value classification do remove the former complete-run checksum. They do not mark skipped runs as verified; the ordinary row-read corruption check remains intact. However, ST14/AC-ST12's sampling page-read hook and assertions are explicitly omitted. The supplied middle-of-blob corruption test passes independently, but shows that corruption is not checked, not that those payload pages are never accessed: reading bytes without verifying integrity would also pass it. No unsupported claim that the new code still checksums entire runs is made.
- Suggestion: use bounded, non-panicking sampling decoding, classify out-of-run offsets as large, and verify the pages actually accessed.

### R12 — Major: Cancelled whole-table samples still read every leaf

- Status: **reopened as a direct regression of `91111a3`**. Round 5 verified the earlier cancellation/finalization fixes; those gather fixes remain present. The newly introduced whole-table traversal loses cancellation while descending the tree.
- Locations: `crates/krummi-tree/src/lib.rs:666`, `:674`, `:677`, `:706`, `:710`; caller `crates/krummi/src/table/statistics.rs:425`, `:428`.
- Failure scenario: renewal of a table of up to 30,000 rows uses `for_each_unchecked`. Store close sets the stop flag; the row visitor returns `false`. The traversal only sets `going = false` and continues returning `Ok(())` to `leaves`. Recursive descent therefore still reads/checks every remaining leaf and branch. `Work::stop` joins this worker, so close waits for the remaining traversal even though it has already observed cancellation.
- **Independent experimental evidence:** construct a valid disposable tree with 1,000 entries, eight-byte keys and 1,500-byte inline values. On the same read transaction, call `for_each_unchecked` first with a visitor returning `false` immediately, then with one returning `true` for every entry. Transaction `pages_read()` deltas are: cancelled traversal **1 callback, 201 node reads**; full traversal **1,000 callbacks, 201 node reads**. Both assertions pass. This verifies the lower-level traversal defect; the source references establish its use by cancelled whole-table renewal. No shutdown latency or maximum time bound is asserted.
- Requirement: S1/ST10: «cerrar detiene el muestreo en curso del hilo sin publicarlo ni guardarlo»; AC-ST7. Skipping callbacks while continuing all remaining page reads does not stop the sampling traversal.
- Suggestion: propagate cancellation through the recursive descent before reading additional nodes.
