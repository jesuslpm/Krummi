### R21 — Minor: ST15 benchmark drops required per-commit estimation rounds

- Location: `crates/krummi-bench/src/worker/tables.rs:606`; notification at `:569`, count at `:612`, coverage at `:705`.
- Failure scenario: run W28 with `KRUMMI_BENCH_ESTIMATES=thread`. Each committed batch sends one notification. While the estimator samples or estimates, more commits can queue notifications. The next `recv` consumes one and the `try_recv` loop discards all remaining notifications, then performs only one round over the columns. The load therefore performs fewer rounds than committed batches. This is introduced by `d4ff730`; `b80503a` leaves it unchanged.
- **Independent experimental evidence:** the coordinator ran the current built worker in a disposable directory under `target/`, with `KRUMMI_BENCH_ROLE=worker`: first `run krummi W23 reduced <tmp>/base` without the estimates variable, then `run krummi W28 reduced <tmp>/updates <tmp>/base/rep-0` with `KRUMMI_BENCH_ESTIMATES=thread`. Both exited 0. W28 reported `rep 0 W28 10000 540888800` and `estimates rounds 9 samples 4`. Its 10,000 rows and batch size 1,000 (`workload.rs:497`) mean **10 commits but only 9 estimation rounds**. The exact count depends on scheduling; the discard loop establishes the causal mechanism directly.
- Corroborating existing evidence: Claude's full-load logs show W28 with 996–997 rounds in `work/st/first/est.json` and 997–999 in `work/st/linux/est.json`, for 1,000 commits. These records corroborate the independent reduced reproduction; they are not substituted for it.
- Requirement: S2/ST15, «un segundo hilo que, tras cada escritura de 1.000 filas, pide una estimación de cada columna», and AC-ST15. The new unit test checks that sampling occurred, but does not assert a round for every commit. Documenting notification merging in a source comment does not amend ST15.
- Impact: the recorded run does not execute the precise requested estimation workload. No storage corruption, performance-threshold violation or material size of timing bias is demonstrated; severity is limited to this measurement defect.
- Suggestion: process one estimation round per commit notification and verify that count before accepting the ST15 measurements.
