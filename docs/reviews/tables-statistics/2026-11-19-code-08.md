<a id="R2"></a>
### R2 — Major: Invalid run offsets discard rows instead of counting large values

- Status: **still open, partially corrected** by `144acf2`.
- Locations: `crates/krummi/src/table/statistics.rs:203`, `:207`, `:227`; dependencies `crates/krummi/src/table/rows.rs:719`, `:729` and `crates/krummi/src/table/row.rs:617`.
- Failure scenario: an end offset of a variable column points outside its run. `stored_len` turns the bounded decoder's error into `None`; the builder treats it as not large and attempts ordinary value decoding. The new `catch_unwind` catches that panic and skips the entire row, including its otherwise readable columns, before incrementing `read` or calling any gather. It never counts the invalid-offset value as large.
- **Independent experimental evidence:** repeated round 7's exact malformed-offset reproduction against the head libraries. Create and close a disposable table `t(id i64 PRIMARY KEY, s string NOT NULL, blob bytes NOT NULL)` with `(1, "x", 200,000 bytes)`. Its run has 25 pages and row header `[1, 0, 2, 1, 0, 0, 0, 120]`. Replace bytes `first_page * 8192 + 16 + 3 .. +7` with little-endian `u32::MAX`, without recomputing integrity. Public `Store::analyze("t", None)` now returns success inside an outer `catch_unwind`. The panic hook still reports the malformed-column panic, but it does not escape. Statistics for **each** of `id`, `s` and `blob` report `origin_rows=1`, `rows_read=0`, `large_fraction=0`. Ordinary `get_row` still returns `ErrorKind::Damaged`. The probe exits 0 after asserting these results.
- Requirement: S1/ST1: «los límites se comprueban, así que un tramo dañado nunca termina en un pánico, y un desplazamiento fuera del tramo cuenta como valor grande». Allowing imprecise statistics from a damaged run does not waive the explicit invalid-offset classification rule.
- **Resolution evidence assessed:** the new `r2_a_corrupt_run_never_panics_the_sample` test (`codex.rs:740`) overwrites the row version as well as other bytes and permits `Err(Damaged)`. It can return from `Reader::decode` before exercising the new catch; the offset-only reproduction above verifies the actual corrected path. ST14/AC-ST12's sampling page-read hook/assertions are still absent. The middle-of-blob corruption test establishes that integrity is not checked for the whole run, but cannot establish which payload pages were accessed: unchecked reads of those pages would also pass it. The original full-run-checksum defect is not asserted to remain.
- Suggestion: classify invalid offsets through bounded sampling decoding and verify actual page accesses.

<a id="R20"></a>
### R20 — Major: Sampling now copies entire large defaults for every old-version row

- Status: **new regression introduced by `144acf2`**, directly in the R2 correction.
- Location: `crates/krummi/src/table/statistics.rs:207`; dependencies `crates/krummi/src/table/rows.rs:710`, `:729`, `crates/krummi/src/table/schema.rs:1110`, `crates/krummi/src/table/value.rs:339` and `crates/krummi/src/table/stats.rs:154`.
- Failure scenario: commit rows, then add a `bytes` column with a 1 MiB default. For the existing rows, that column has no stored position in their old schema version, so `stored_len` returns `None`. `row.value` returns the default borrowed from the catalog. The new unconditional `into_owned()` copies its entire payload for every sampled row. Only afterwards does `Gather::add` classify it as large and discard the copy. The old builder passed the borrowed value directly to `Gather::add`, which checked its length before encoding or reading its contents. The shared builder affects estimates, analyze and renewal, including while a write retains its turn.
- **Verifiable technical evidence and independent reachability probe:** a valid public-API construction with three committed rows, followed by `add_column(blob, bytes default = 1,048,576 bytes)`, succeeds. Reading an old-version row returns `Value::Bytes(Cow::Borrowed(...))` of that length; `into_owned()` produces `Cow::Owned`. Analyze reports three sampled rows and `large_fraction=1`. Source tracing establishes that the new line copies that borrowed payload once per row. A whole-table sample of 30,000 such rows therefore adds **31,457,280,000 bytes of copying**, calculated from the code path, not measured as a benchmark or peak allocation. `schema.rs:300` accepts this default under the catalog-entry size limit.
- Requirement: S1/ST1: «Los **valores grandes**, los de `string` o `bytes` de más de 2.048 bytes [...] no se leen: el muestreo solo cuenta que la fila tiene uno». This reintroduces sampling work proportional to large payload size on valid data, even though ordinary stored large columns are skipped.
- Suggestion: classify defaults as well as stored fields before materializing or copying their payloads.

### R13 — Major: Failure coverage remains incomplete and commit tests still lack phase isolation

- Status: **still open, partially corrected** by `144acf2`.
- Locations: `crates/krummi/tests/table_statistics/codex.rs:569`, `:663`, `:808`; `crates/krummi/src/table/stats_fault_tests.rs:106`. Dependencies: `crates/krummi-pager/src/journal.rs:789`, `crates/krummi-pager/src/scratch.rs:636`.
- **Coverage evidence:** inventory of the complete statistics tests and all prior reports/resolutions. The new renewal disk-full test adds useful save-phase coverage: renewed statistics remain in memory, writes continue, the next estimate retries saving, and reopen sees the saved result. The new foreground analyze test asserts the I/O class, retained memory and subsequent write refusal. These additions close parts of the reported gap.
- Still missing are sampling read-I/O cases with their distinct class, renewal preservation/retry behavior and foreground transaction effects, and the remaining foreground sampling/analyze failure matrix. For example, there is no deterministic `Store::analyze` table-page-damage case requiring `ErrorKind::Damaged`; the new corrupt-run test accepts success too. Existing snapshot-OOM tests and pre-commit save-page errors do not cover those other phases.
- The attempted phase-isolation correction is insufficient. Both commit-I/O tests inject all future `Op::Write` failures after the initial data commit and `make_durable()`. That method only waits for the journal's durable transaction ID; it does **not** wait for the initial commit's asynchronous transfer into the data file. A fault may still hit that transfer, making the store refuse writes before the intended statistics commit; foreground analyze can even fail while asking for its write turn. The original successful data commit already awaited journal durability.
- **Independent controlled experimental evidence:** on a disposable engine, pause the initial data transfer with `set_transfer_hook` immediately before its write, commit the initial data, and call `make_durable()`. It returns while that transfer remains paused. Inject `Op::Write`, release the transfer and wait through `checkpoint()`: the initial transfer fails with `ErrorKind::Io`, with exactly one write attempt. Clearing the fault permits close to succeed. This demonstrates the isolation limitation, not a runtime failure of the statistics error contract. Round 6's separate checkpointed statistics-commit reproduction and its two close/recovery branches were consulted rather than unnecessarily repeated; that evidence does not repair these repository acceptance cases.
- **Resolution evidence assessed:** mapped data-page reads indeed lack a dedicated read-I/O injector; `Op::Read` targets journal reads, and `Engine::set_page_fault` targets write-transaction page operations. This explains the stated testing limitation. Damage does not demonstrate the separate I/O error-class contract, so treating it as equivalent does not close the requirement.
- Requirement: S1/S4, ST3/ST7/ST9 and AC-ST8: «dados los mismos fallos al leer la muestra en una estimación, entonces la estimación falla con su clase»; «y los mismos fallos al analizar en el almacén los informa analizar con su clase». These are acceptance-coverage defects; unexecuted scenarios are not presented as additional proven runtime failures.
- Suggestion: complete the remaining phase-specific fault cases and isolate statistics commits from earlier transfers.
