<a id="R1"></a>
### R1 — AC-X10 excludes errors that the opening rules require

- **Severity:** minor.
- **Section / IDs:** Acceptance criteria / AC-X10; X4 and X10; inherited A1.
- **Location:** `docs/prd/krummi/trees-fixed-size.prd.md:253`, especially line 259.
- **Problem:** the criterion starts with an existing tree but says that Create new does not fail. A literal test would conflict with the inherited opening semantics. The intended exclusion is damage in the tree's own pages, rather than all errors.
- **Evidence:** AC-X10 says: “los modos Abrir, Crear nuevo y Abrir o crear, Existe, Tipo, Listar, Renombrar sin sobrescritura y el número de entradas no fallan”. A1 in `docs/prd/krummi/trees-keys.prd.md:36` requires: “**Crear nuevo**: crea un árbol vacío; si ya existe, falla con la clase nueva de **árbol ya existente**.” X4 inherits A1. X10 at `trees-fixed-size.prd.md:49` already gives the intended qualification: “nunca fallan con daño en las páginas del propio árbol”.
- **Impact:** an acceptance test generated literally from AC-X10 would require success where the product rule requires TreeAlreadyExists. This is a wording defect, not an unresolved product choice.
- **Suggestion:** qualify the criterion as excluding damage in the tree's own pages while preserving the normal validation errors.
- **Status:** open.

### R2 — Claimed annotations in affected PRDs are missing

- **Severity:** minor.
- **Section / IDs:** Objective and context; Annotations to other PRDs / X1–X15, especially X3, X12, X14 and X15.
- **Location:** `docs/prd/krummi/trees-fixed-size.prd.md:31` and `:330`.

- **Impact:** readers following the earlier PRDs do not discover the declared extensions and format update. The child states the intended behavior explicitly, so this is a documentation synchronization defect rather than a missing product decision.
