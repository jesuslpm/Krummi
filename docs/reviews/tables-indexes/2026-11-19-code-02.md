## Open findings

<a id="R4"></a>
### R4 — Major: Collision checking aborts the process when copying another table's default

**Location:** `crates/krummi/src/table/catalog.rs:805`; dependencies `catalog.rs:217`, `schema.rs:1182`, `value.rs:338`. Introduced by R2's fix, `2d2912b`.

`store_knows` now calls `find_table` for every table while drawing an index identity or state. `find_table` fully decodes the schema; `TableSchema::decode` converts each default to an owned value with `Value::into_owned`. Copying a large string, bytes or vector default uses infallible allocation. Therefore creating an index on a small, empty table can abort because of a large default in an unrelated table. `drop_index` reaches the same helper (`index.rs:760–761`). The entry-key/payload reservations repaired for R1 do not cover this new allocation.

**Concrete scenario and experimental evidence:** commit empty `t(id i64 not null, n i32)` and unrelated `u(id i64 not null, p string default <2 MiB string>)` in a temporary store. Open `t` with allocation allowed. Arm a `GlobalAlloc` wrapper around `System` that returns null for allocations/reallocations of at least 1 MiB only during `create_index(t, ix(n))`. The isolated executable prints:

```text
arming allocator during create_index on empty t; unrelated u has a 2 MiB default
memory allocation of 2097152 bytes failed
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
catalog_oom_exit_code=-1073740791
```

The host operation never returns `OutOfMemory` or applies T11; the isolated process exits with `0xC0000409`. Setup and schema persistence succeed before arming. The refused size matches the default's content copy. At the base, index creation did not scan or decode `u`; the new use of the pre-existing decoder introduces this failure. This is a controlled reproduction of allocation refusal, without exhausting the review host. No corruption or undefined behavior is claimed.

**Requirement:** S1/S3, inherited P13/T11 allocation-failure handling and preservation of correctness during the R2 correction. IX2 requires creation to report memory exhaustion rather than terminate the process. These content-sized allocations are separate from the small bounded allocations explicitly excluded by the R1 resolution.

**Coverage gap:** the new fault-injection tests exercise `Op::Alloc` reservations, not infallible default copies during catalog decoding. They pass despite this failure.

**Suggestion:** inspect catalog identities and history roots without copying defaults, or make required copies fallible and propagate failures through transaction tracking.

<a id="R2"></a>
### R2 — Major, still open: Collision checks skip identities of non-table catalog objects

Follow-up of [2026-11-19-code.md#R2](2026-11-19-code.md#R2).

**Location:** `crates/krummi/src/table/catalog.rs:802–804`; callers `table/index.rs:727`, `:729`, `:761`.

The fix now rejects the table/column/state examples in the original report, but `store_knows` skips every catalog entry whose kind is not `Table`. Normal, multi-value and fixed-size trees and sequences also have catalog identities. An index identity or state can consequently reuse one already known by the catalog.

**Concrete scenario and experimental evidence:** create tables `t` and `u` with the original deterministic draws, then create a normal tree, a multi-value tree and a fixed-size tree. Their counter-generated identities are `0`, `1`, `2` (`krummi-tree/src/catalog.rs:255–261`; table identities use the separate random source). Supply `[0, 1, 50, 60]` for creating `t.ix(n)`, and `[2, 70]` for dropping it. Describe returns:

```text
create: index=0 state=1
drop: state=2
```

The transaction commits. The available replacement draws `50`, `60` and `70` are not consumed. This independently extends the original R2 reproduction to the catalog kinds excluded by the fix; the previous source check also excluded them. No row corruption or frequent random collision is claimed.

**Requirement:** S1/S3, IX6 and AC-IX11. IX6 states «se vuelven a sortear si coinciden con uno que el almacén conoce». Design document 11:247–258 explicitly includes values already present in the store catalog; it does not exempt trees or sequences. The shared catalog and existing tree identities are established by N1/E2 and the schema PRD's starting state. Different identity generators do not exempt known values from this check.

**Verification of the resolution's evidence:** the exact original table/column reproduction now returns index identity `50`, creation state `60` and drop state `70`, as claimed. A separate probe also rejects retired index identity/state `140`/`150` from another table's history and its current state `160`, accepting `170`/`180`. Those subcases are verified resolved. The broader known-catalog requirement remains unmet.

**Suggestion:** compare against every catalog entry's identity before applying table-specific schema/history checks.
