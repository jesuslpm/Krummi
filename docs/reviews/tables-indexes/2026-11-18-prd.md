## Findings

<a id="R1"></a>
### R1 — Major — Included primary-key columns have conflicting ownership contracts

- **Location:** Decisions / IX1 and IX8; Acceptance criteria / AC-IX3 (`docs/prd/krummi/tables/tables-indexes.prd.md:45`, `:52`, `:214`).
- **Status:** open.
- **Problem:** A primary-key column explicitly listed among an index's included columns falls under both the borrowed-value rule and the owned-copy rule. The PRD does not establish which rule wins.
- **Evidence:** IX1 permits: «Las columnas de la clave primaria pueden estar en la clave del índice o entre sus incluidas». IX8 requires included columns to return «sin copia el texto, los bytes, los vectores y el JSON», but also requires values of primary-key columns to return «decodificados en una copia propia de la aplicación, también el texto y los bytes». AC-IX3 explicitly exercises «una columna de la clave primaria en la clave del índice y otra entre las incluidas», while retaining «el texto, los bytes y los vectores incluidos sin copia, los de la clave en una copia».
- **Observable readings:** For a table with primary key `id: string` and an index on another column that includes `id`, one implementation returns `id` borrowed from the included payload; another returns an application-owned decoded copy because `id` belongs to the primary key. Ownership and copying behavior differ. IX8 exposes each column only once, so separate positions cannot satisfy both rules. AC-IX3 therefore lacks an unambiguous expected result for this supported case.
- **Suggestion:** Specify which ownership rule takes precedence for included primary-key columns and align AC-IX3 with it.
