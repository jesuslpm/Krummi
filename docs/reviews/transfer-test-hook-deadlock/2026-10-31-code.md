## Findings

No findings. No open defects or base-only advisories were identified in the requested scope.

The change at `crates/krummi-tx/tests/transfer.rs:251` correctly shortens the mutex guard's lifetime. `Shared::flush_locked` clones the hook before invoking it (`crates/krummi-pager/src/scratch.rs:664`); clearing the installed hook (`scratch.rs:447`) does not cancel that cloned callback. The callback locks the captured vector (`transfer.rs:237`), whereas close joins the transfer worker (`scratch.rs:487`, `scratch.rs:497`). The base could therefore retain the vector's guard while waiting for a worker blocked on that same mutex. Cloning the vector drops the temporary guard at the statement boundary, removing that wait cycle.

This conclusion is supported by source-level concurrency analysis, independently checked by the coordinator and delegated reviewer. The base deadlock was not experimentally reproduced, and the passing test run does not establish exhaustive scheduling coverage.
