### R1 — verified resolved (original severity: major)

**Original finding:** [Growth waits for transfer even when the maximum leaves ample room](2026-10-27-code.md#R1).

**Reviewed fixes:** `ce4f264` changes the transfer condition; `a7937d5` increases the regression test's observation timeout to 30 seconds.

**Source evidence:** `WriteTransaction::reserve` at `crates/krummi-tx/src/transaction.rs:530` now requests a pre-growth flush only if `min(growth_target, max_size) + memory > max_size`, using saturating addition. When the entire growth and counted memory fit, including equality, it reaches `ensure_pages_within` without requesting `Demand::Flush`. This removes the dependency identified by R1 and satisfies the relevant J5/AC-J17 progress requirement: “entonces las dos terminan sin esperar al traslado”.

**Executed reproduction coverage:** `growth_with_ample_room_does_not_wait_for_a_running_transfer` at `crates/krummi-tx/tests/free_space.rs:1013` passed. It uses a 64 MiB maximum, leaves versions pending, holds a transfer in its hook and verifies that a separate writer allocates and commits before the transfer is released. It also verifies that the store grew. The timeout change preserves this ordering assertion. The prior failing revision was not re-executed; the historical RED claim remains historical evidence, while the current GREEN and source argument independently establish the correction.

**Regression analysis:**

- `growth_target` at `crates/krummi-pager/src/pager.rs:33` extracts the previous expression unchanged; `next_size` reuses it at line 605. Pager growth and the transaction's prediction therefore share the same growth rule. The effective growth limit remains the maximum minus counted memory (`transaction.rs:540–545`, `transaction.rs:558`).
- Scratch accounting can only decrease during this reservation: `ScratchWriter` excludes another writer (`scratch.rs:228`), and the counter increases only when that writer publishes (`scratch.rs:891–896`). Transfer and garbage collection reduce it. A skipped flush cannot become necessary because another writer added versions between the condition and growth. This confirms the substantive evidence behind the RDD cap-prediction dismissal in ODD L9.
- When pending versions constrain growth, the existing flush, recomputation and maximum-size error behavior remain. Both `growth_within_the_maximum_size_ignores_versions_no_read_needs` (`free_space.rs:980`) and `growth_within_the_maximum_size_counts_versions_a_read_needs` (`free_space.rs:1069`) passed, covering J7 and T14. `ac_f18_the_maximum_size_in_a_temporary_store` also passed.
- Transfer failures still propagate through `reserve`; the surrounding first-failure tracking and commit durability path are unchanged. Extracting the pager expression does not change either storage mode's mapping/allocation behavior. The workspace's existing transfer, journal, recovery and allocation-failure tests passed.

**Status:** verified resolved. No finding from the original report remains open.
