## Findings

### R1 — Major: Equivalent predicates produce different equality estimates

<a id="R1"></a>

- **Location:** `crates/krummi/src/table/estimate.rs:356`; `crates/krummi/src/table/stats.rs:112`.
- **Failure:** Equality validation encodes the folded predicate but determines `large` using `is_large`, which also checks the original spelling's length. A long spelling that folds to a short frequent value is routed to `found.large` at `estimate.rs:406`, bypassing the matching frequent value. Equivalent predicates can therefore produce estimates of zero and one for the same existing row.
- **Reproduction (executed):** Create a temporary store with integer primary key `id` and `ci_ai` string `t`; insert `(1, "Ana")`, analyze `t`, then estimate equality with `"ana"` and with `format!("a{}na", "\u{301}".repeat(1024))`. Both fold to `ana`. Public API output:
  ```text
  short bytes=3 folded="ana" estimate=1
  long bytes=2051 folded="ana" estimate=0
  ```
- **Requirement:** S1, IC7/IC8, AC-IC8. IC7 explicitly states: «En una estimación, la forma plegada decide si un valor es grande». The stored-value sampling rule that also counts long originals does not authorize using original predicate length.
- **Introduction/coverage:** Binary predicates did not identify these spellings as equivalent at the base. Existing collation statistics tests exercise expansion and short equivalent spellings, not a long predicate that shrinks below the limit.
- **Suggestion:** Classify estimation predicates by folded length separately from the classification of stored values.

### R2 — Major: Composite-index statistics read oversized original texts

<a id="R2"></a>

- **Location:** `crates/krummi/src/table/statistics.rs:234` and `:254`; newly reachable through collated prefix keys constructed at `:167`.
- **Failure:** Per-column gathering skips originals over 2,048 bytes, but index-prefix gathering unconditionally touches every key column's run pages and reads/folds its entire value. A `ci_ai` text can now be much larger than 2,048 bytes in the row while fitting in the index after folding. Analysis of the table then reads all pages of that large original, violating the sampling contract and making sampling work scale with the oversized text.
- **Reproduction (executed):** In a temporary store, create integer primary key `id`, `ci_ai` string `t`, integer `n`, and index `(t,n)`. Insert one row with `t = format!("a{}", "\u{301}".repeat(100000))` (200,001 bytes, folded to `a`) and `n = 1`, then commit. Measure `Store::statistics_pages_read()` around each call:
  ```text
  column-only pages=1
  all-column pages=25
  ```
  The calls are `store.analyze("t", Some("t"))` and `store.analyze("t", None)`; the other scalar and all row metadata fit in the first page. Source tracing confirms prefix gathering reads the extra 24 pages.
- **Requirement:** S1, IC8 and inherited ST1/AC-ST12. IC8 retains «los textos de más de 2.048 bytes, que no se leen, como dice ST1».
- **Introduction/coverage:** At the base this text could not be in an index because its binary key exceeded the key limit. The existing large-value sampling tests do not cover an indexed original that shrinks under collation.
- **Suggestion:** Gather folded prefix values without reading oversized row originals.

### R3 — Major: Duplicate original text storage rejects rows below the row limit

<a id="R3"></a>

- **Location:** `crates/krummi/src/table/index.rs:459`, `:475` and `:567`.
- **Failure scenario:** Define a single-column `ci_ai` string primary key and a descending secondary index on that same column. This definition is permitted by `check_definition` at `index.rs:312`: the redundant-primary-key check only excludes the ascending form. Supply `"a" + U+0301 repeated 67,108,864 times`. The original is 134,217,729 bytes; the stored row is 134,217,732 bytes, below the 268,435,456-byte row maximum. It folds to one byte, `a`, and its descending-index element plus primary key occupy only seven key bytes.
- **Causal evidence (source proof; no large allocation experiment):** `originals` chains index-key IDs and primary-key IDs without deduplicating the underlying column. The same original is consequently serialized twice in the entry value. The two payload copies alone occupy 268,435,458 bytes, already exceeding `MAX_ROW` before entry metadata. The check at `index.rs:569` returns `TooLarge::Included` instead of admitting the valid row/index. Both insertion with the index present and index creation over that row reach this path.
- **Requirement:** S1, IC7: «el texto original que guarda una entrada de índice para devolverlo (IC5) no cuenta para el máximo de la clave: lo limita solo el máximo de la fila».
- **Introduction/coverage:** This is an introduced restriction from the new original-text payload, not a pre-existing binary key limit. Existing shrinkage tests use much smaller originals and do not overlap the collated index key and primary key near the value limit.
- **Suggestion:** Store each column's original once and map all corresponding key elements to that shared payload.

### R4 — Minor: Collated index keys return borrowed texts despite the owned-copy contract

<a id="R4"></a>

- **Location:** `crates/krummi/src/table/index_scan.rs:236`; `crates/krummi/src/table/index.rs:495`.
- **Failure:** `IndexEntry::element` returns `EntryLayout::original` directly. That function reads a string from the entry's row payload, yielding `Value::String(Cow::Borrowed(_))`. Thus collated index-key and primary-key texts borrow the transaction's pages, while ordinary key texts are decoded into owned copies. Text contents are correct and Rust still enforces their lifetime, so this is a limited-impact ownership-contract defect, not a demonstrated memory-safety failure.
- **Reproduction (executed):** Using the R1 table with an index on `t`, obtain its entry and test `matches!(entry.get("t"), Some(Value::String(Cow::Owned(_))))`. Output: `index key owned=false`.
- **Requirement:** S1, IC5/AC-IC6 and IX8. IC5 requires «decodificado en una copia propia de la aplicación como los demás valores de la clave (IX8)». The public documentation at `index_scan.rs:212` likewise promises a copy for key values.
- **Coverage:** The new original-text test converts the returned values with `into_owned()` before comparing them, masking this distinction.
- **Suggestion:** Return an owned original for index-key and primary-key elements while preserving borrowing for included columns.
