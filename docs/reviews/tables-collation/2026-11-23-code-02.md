## Findings still open

### R2 — Major: Composite-index statistics read oversized original texts

<a id="R2"></a>

- **Status:** still open, partially corrected by `aca3dd3462355aac5da9ba930223d782ad06a490`. The original stored-row/page-read reproduction is fixed; oversized defaults for older rows still bypass the filter. This preserves [the original R2](2026-11-23-code.md#R2), rather than creating a duplicate finding.
- **Location:** `crates/krummi/src/table/statistics.rs:241` and `:270`; dependencies `crates/krummi/src/table/rows.rs:759`, `:790` and `:742`.
- **Concrete failure:** insert a row with integer `id` and `n=1`; then add a non-null `ci_ai` string column `t` with default `format!("a{}", "\u{301}".repeat(100_000))` (200,001 bytes). Create index `(t,n)` and analyze all columns. The column gather correctly counts a large value without folding it, but the prefix gather reads and folds the complete default for every old row.
- **Causal evidence:** an added column is absent from the old row layout, so `stored_len` returns `NotStored`. The new prefix filter's wildcard arm treats it as readable. `row.value` resolves the borrowed catalog default and `KeyColumn::encode` traverses/folds it. Unlike the column gather's `is_large` check, this route never checks the default's original length before encoding. Work therefore scales with the entire oversized default for each sampled row and index containing it. No timing measurement is claimed.
- **Independent public API reproduction (executed at HEAD):**
  ```text
  R2 default: column large=1 prefix distinct=1 frequent=[([String("a"), I64(1)], 1.0)]
  ```
  Keeping the folded `a` in the prefix demonstrates that the oversized default was read through that path. The default is in catalog memory: this reproduction establishes unwanted traversal/folding, not extra row-run pages.
- **Requirement:** S1, IC8 and inherited ST1: «los textos de más de 2.048 bytes, que no se leen, como dice ST1». Defaults used to read old rows remain subject to the sampling rule.
- **Coverage/lineage:** the new R2 test only uses a physically stored text. Its original case now passes; independent probes also confirm that a large stored text in each of three index-key positions adds no sampling pages and preserves preceding readable prefixes. The old-default route remains untested by that regression. This is the remaining route of the collation finding, not a reopening of the separate historical statistics R20.
- **Suggestion:** classify the length of resolved defaults before encoding them into prefix statistics.

### R5 — Major: Joint estimates treat the new large-value fraction as ordinary combinations

<a id="R5"></a>

- **Status:** new regression caused by the R2 correction `aca3dd3462355aac5da9ba930223d782ad06a490`.
- **Location:** `crates/krummi/src/table/estimate.rs:974`–`:979`; producer `crates/krummi/src/table/statistics.rs:289`–`:291`.
- **Concrete failure:** create an integer-PK table with `ci_ai` string `t`, integer `n`, and non-unique index `(t,n)`. Insert two rows: `t="a" + U+0301 repeated 100,000 times`, `n=1`; and `t="s01"`, `n=1`. Analyze all columns. For the short, nonexistent predicate `t="z"`, the column estimate is zero but `EqualColumns([("t","z"),("n",1)])` estimates one row with `joint=true`.
- **Causal evidence:** the correction counts the skipped original in the prefix's `large` fraction instead of its ordinary combinations. The dependent estimator ignores `found.large` and the checked predicates' large flags. Its unmatched-combination formula `(1 - frequent) / remaining_distinct` treats all omitted large mass as ordinary residual mass. Here the sole ordinary combination is frequent with fraction 1/2, so it assigns the remaining 1/2 to the nonexistent short combination.
- **Independent public API reproductions (executed at HEAD):**
  ```text
  R5: rows=2 predicate_bytes=1 column=0 joint=1 joint_flag=true
  R5: rows=13 predicate_bytes=2049 column=1 joint=1.5000000000000004 joint_flag=true
  ```
  The second case has twelve ordinary distinct strings `s01..s12` plus one oversized original folding to `a`, all with `n=1`; the predicate is `"z".repeat(2049)`. A large equality must estimate the large fraction (one row), but the prefix estimates 1.5 instead.
- **Requirement:** S1, IC7/IC8, ST2 and ST18. ST18 requires the fraction of each group «como una igualdad de ST2». ST2 excludes large values for a non-large equality and uses the large fraction for a large equality.
- **Introduction evidence:** source comparison with the review base shows that prefix gathering previously encoded every combination, including the oversized original's short folded form, and never called `add_large` for this case. With two rows both combinations were frequent and an absent short combination had zero residual mass. The correction introduces nonzero `large` in the producer without updating its consumer, even though the consumer is outside the diff.
- **Suggestion:** apply the ST2 large-value rules when estimating a prefix group, including folded predicate classification.
