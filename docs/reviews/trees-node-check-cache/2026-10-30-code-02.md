## Open findings

<a id="R3"></a>
### R3 — minor — AC-C8 hangs instead of reporting a reader or writer failure

**Location:** `crates/krummi/src/check_tests.rs:421`, with the failure detector at `:450` and the success-only completion signal at `:475`.

The R2 fix makes healthy readers continue while `!done`, even after completing `ROUNDS`. Only the successful writer path sets `done = true`. If a reader's snapshot/damage assertion or an engine call fails, `two_rounds` detects the finished reader and panics. Unwinding then leaves `thread::scope` waiting for the remaining readers, which continue indefinitely because `done` remains false. A panic in the writer before line 475 has the same consequence. A detected regression can therefore hang the workspace test run until an external timeout instead of producing its failed-test result.

**Evidence type: reproduction and verified control flow.** The coordinator compiled `lib.rs` and `check_tests.rs` from stdin against the current engine dependencies, inlining the test module and omitting unrelated test modules. Repository sources were never edited. Immediately before `let mut seen = BTreeSet::new();` in the reader closure, the reproduction inserted:

```rust
static INJECT_ONCE: AtomicBool = AtomicBool::new(true);
if INJECT_ONCE.swap(false, Ordering::SeqCst) {
    panic!("review injected single reader failure");
}
```

A diagnostic after `finished.store(count, Ordering::SeqCst)` printed when each healthy reader reached `ROUNDS`. Neither the loop bounds nor its cancellation condition was changed. The executable ran only `check_tests::ac_c8_concurrent_reads_with_competing_slots`, with `--exact --nocapture --test-threads=1`. Its output included:

```text
review injected single reader failure
a reader stopped while the writer ran
review reader reached ROUNDS=1000; done=false
review reader reached ROUNDS=1000; done=false
review reader reached ROUNDS=1000; done=false
```

The process remained alive at 20 seconds and was terminated by the bounded verification harness; it never printed a test result. The loop condition explains why waiting longer cannot finish those readers. An earlier eight-second run also timed out. Build/test artifacts are `target/review-node-check-cache-reader-panic.exe` and its `.stdout.log` / `.stderr.log` files.

For comparison, the same once-only reader panic injected before `let mut node_reads = 0;` in the test from `fc57e47`, compiled against the same current engine dependencies, produced `FAILED` and exit 101 in 0.12 seconds. Its artifact is `target/review-node-check-cache-base-reader-panic.exe`. This isolates the regression to the new test coordination rather than the engine.

**Related requirement:** S8 / AC-C8 and the verification mechanism introduced to resolve original R2. The impact is limited to test termination and diagnostics; this is not evidence of an engine race, corruption or a false passing result.

**Suggestion:** ensure readers receive effective cancellation during unwinding before the scope waits for them.

**Status:** open; introduced by `f95c57fa4f3c778ca42169ab9ba630e02a76a2da`.

### R2 — verified resolved

Original: [2026-10-30-code.md#R2](2026-10-30-code.md#R2), major, insufficient concurrent acceptance coverage. Reviewed disposition: `fixed` in `f95c57fa4f3c778ca42169ab9ba630e02a76a2da`.

The current test requires four readers, at least 1,000 complete rounds per reader, and all 21 expected generations in each reader's observed set. Every round reads the catalog, the good tree's paths for all 24 keys, and the damaged node, asserting snapshot consistency and the damage page. Readers cannot finish normally before the writer signals completion.

Before the first commit and after every commit and transfer, `two_rounds` requires two more completed rounds from every reader. At most one round can have started before that progress checkpoint, so each reader performs a full round begun after the step. The writer cannot skip a generation before every reader has exercised it. After transfer, `scratch_bytes() == 0` and a further checkpoint establish reads of transferred contents while the workload is still active. The two sequential scheduling counterexamples in the original report no longer satisfy the test.

The test passed independently in the workspace run, on both disk and temporary stores. R3 is a separate failure-path regression in its new coordination; it does not preserve the original coverage defect.
