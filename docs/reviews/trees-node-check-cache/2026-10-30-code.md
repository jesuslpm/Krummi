### R1 — major — Cache allocation can abort the process when opening a store

**Location:** `crates/krummi-pager/src/checked.rs:70`; opening callers at `crates/krummi-pager/src/pager.rs:201` and `:912`.

`Checked::new()` uses infallible `collect()` to allocate 65,536 `AtomicU64` slots, adding a 524,288-byte allocation to every store opening. Its return type cannot report allocation failure, and there is no fallback. If earlier opening allocations succeed but the allocator rejects this additional buffer, opening either a disk or temporary store aborts the entire application instead of returning control to its caller. This is an introduced failure point; preexisting smaller infallible allocations do not remove this independently reachable failure.

**Evidence type: reproduced allocation failure and verified call chain.** The coordinator compiled a standalone harness from stdin, including the reviewed `checked.rs` unchanged. A custom global allocator returned null only for an allocation of exactly 524,288 bytes and delegated other allocations/deallocations to `System`. Calling `Checked::new()` printed:

```text
before Checked::new
memory allocation of 524288 bytes failed
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
Harness exit: -1073740791
```

The process exited with `0xC0000409` and never reached the following `after Checked::new` marker. The executable is a verification build artifact under `target/review-node-check-cache-oom.exe`; no source file was created. The essential harness, compiled with `rustc --edition 2024 -A dead_code -o target/review-node-check-cache-oom.exe -`, was:

```rust
use std::alloc::{GlobalAlloc, Layout, System};
struct FailChecked;
unsafe impl GlobalAlloc for FailChecked {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        if layout.size() == (1 << 16)
            * std::mem::size_of::<std::sync::atomic::AtomicU64>()
        {
            std::ptr::null_mut()
        } else {
            unsafe { System.alloc(layout) }
        }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        unsafe { System.dealloc(ptr, layout) }
    }
}
#[global_allocator]
static ALLOC: FailChecked = FailChecked;
#[path = "C:/projects/Krummi/crates/krummi-pager/src/checked.rs"]
mod checked;
fn main() {
    eprintln!("before Checked::new");
    let _checked = checked::Checked::new();
    eprintln!("after Checked::new");
}
```

**Violated requirements:** C5 (`trees-node-check-cache.prd.md:49`) says the cache size "no hace fallar ninguna operación". P13 (`pager.prd.md:41`, also referenced by the tree parent's B11) requires: "si el sistema no da la memoria que el almacén necesita para abrirse o crecer, en cualquiera de los dos modos, la operación falla con la clase de error de memoria agotada". No exception authorizes this new fatal allocation. The existing fallible reservation helper in `scratch.rs:105` explicitly avoids process abort for engine allocations; current allocation-fault tests do not intercept this `collect()`.

**Suggestion:** allocate the cache fallibly and handle its failure according to C5/P13 without terminating the application, with a deterministic allocation-failure test.

**Status:** open.

### R2 — major — AC-C8 can pass without overlapping readers, writes and transfers

**Location:** `crates/krummi/src/check_tests.rs:402`, reader/writer loops at lines 403–434.

The acceptance test spawns four finite reader loops and then performs twenty write/commit/transfer generations. There is no barrier or handshake coordinating their progress and no assertion that a reader observed a generation change or that a transfer occurred while readers were still exercising the workload.

**Evidence type: verifiable scheduling argument.** A permitted execution runs all four reader closures to completion before the parent reaches its first commit. Another runs all writer generations before the readers begin. Both satisfy the current assertions: each reader only checks consistency within its own snapshot and the static damaged node's error. `thread::scope` joins the closures but guarantees neither their simultaneous progress nor overlap with the writer. Calling `transfer_now()` does not establish that readers exercised transferred versions during the concurrent phase. Thus a passing run can exercise only the static cache workload and sequential writing, leaving the required transition under contention unverified.

The loop also stops after only twenty full read rounds per thread: with `KEYS = 24`, line 421 adds `2 + 2 * KEYS + 1 = 51` estimated internal node visits per round. Each worker performs 480 good-tree Gets and twenty damaged-node Gets. Its 1,020 aggregate internal visits should not be presented as one thousand repetitions of the full scenario; the overlap deficiency holds regardless of how the repetition wording is interpreted.

**Violated requirement:** S8 / AC-C8 (`trees-node-check-cache.prd.md:178`): "cuando cuatro hilos con transacciones de lectura los leen a la vez, al menos mil veces cada uno, mientras una escritura los cambia y se trasladan". This is a demonstrated acceptance-coverage gap, not evidence of an actual engine race. The closing report's PASS for AC-C8 overstates what the test establishes.

**Suggestion:** coordinate reader progress, commits and transfers and assert that the required old/new versions and transferred contents were exercised while readers remained active, with explicit workload repetition counts.

**Status:** open.
