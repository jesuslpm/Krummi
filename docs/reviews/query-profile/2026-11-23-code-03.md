### R3 — major — The trial's confidence rule remains miscalibrated

- Lineage: [original R3](2026-11-23-code.md#R3), [first follow-up R3](2026-11-23-code-02.md#R3).
- Status: **still open; partially corrected** by `385be4a`, verified at the supplied head.
- Location: `docs/design/tables/15-query-profile-and-tuning.md:488`–498; related experiment at lines 894–897.
- Verified improvement: the earlier counterexample (Q: 29 executions at 1 page and one at 1,000; P: 30 at
  10) now gives sample variance `33,266.7` and `z = 0.4294294294`. It continues or ends inconclusive rather
  than forcing P. Random assignment, separate trial aggregates and an inconclusive outcome remain improvements.
- Remaining problem: a minimum of 30 observations and the observed variance do not establish the claimed
  confidence for rare expensive values. Reusing fixed thresholds after further observations also fails to
  control the stated error even under approximately normal costs. These are deficiencies in R3's new evidence
  rule, not separate unrelated findings.

**Concrete failure: a uniformly worse plan is still forced.** Costs in logical pages:

| Parameter | Last good plan P | Candidate Q |
|---|---:|---:|
| A | 10 | 1 |
| B | 1,000,000 | 100,000 |

Q is ten times cheaper for every parameter. Historical P executions using A and Q executions using B make Q
suspect under lines 470–476. The trial receives three B executions followed by 197 A executions, such as a brief
batch of expensive keys followed by ordinary traffic. Catalog tokens remain valid and no accepted plan intervenes.

With probability `1/8`, all three B executions are assigned to Q. P then observes only A, with mean 10 and
variance zero. At any evaluation in these 200 executions with both arms having at least 30 observations, Q has
three B executions and `n - 3` A executions, for `30 <= n <= 170`. The new formula gives:

- `z(30) = 1.7916442972`;
- `min(z(30), ..., z(170)) = 1.7236315652 > 1.645`.

It therefore declares Q regressed and forces P. This also holds if the consumer evaluates only at a flush after
execution 200. Conditional on the first three assignments, let `X ~ Binomial(197, 1/2)` count the remaining Q
assignments. Both arms have 30 observations when `27 <= X <= 167`; failure of this condition has probability
`2.6999826497e-25`. Thus this event alone forces the uniformly worse P with probability essentially **12.5%**.
Subsequent A executions cost ten times Q until expiry. The conclusion is an arithmetic counterexample under
the specified randomization, not an implementation failure or a demand for zero statistical error.

**Independent regression in the claimed normal-case error control.** Lines 488–490 evaluate again when the
result is inconclusive, but use the same fixed `+/-1.645` boundary. In a reproducible simulation with benign,
approximately normal integer costs, P costs `1000 + round(100 * Normal(0, 1))` and Q costs `2 * P + 1` for the
same parameter. Q is strictly more than twice as expensive for every parameter. Each execution independently
chooses an arm with probability 1/2; each flush adds 60 executions. The procedure stops at its first crossing:

| Evaluation policy | False clearance of Q, out of 5,000 trials |
|---|---:|
| First eligible evaluation only | 260 (5.20%) |
| Repeated evaluation, at most 10 flushes | 740 (14.80%) |
| Repeated evaluation, at most 20 flushes | 932 (18.64%) |

Clearing Q promotes a genuinely regressed candidate to last good. Ten ordinary 15-minute flushes take 2.5 hours;
no specified trial bound or evaluation schedule excludes this case. A time limit caps the number of evaluations
but does not calibrate their joint error. The boundary-case companion simulation with `Q = 2 * P` and 100 flushes
gave 28.24% upper and 28.94% lower crossings, versus 5.24% and 5.36% at the first eligible evaluation.

- Evidence: independently executed arithmetic and exact binomial calculation for the uniformly better Q;
  independently executed seeded simulation for the repeated-evaluation problem, reproduced below. The distinction
  between fixed-time confidence intervals and intervals valid at arbitrary stopping times is also supported by
  this [primary statistical paper](https://arxiv.org/abs/2103.06476), abstract. The numeric findings come from our
  calculations, not from that paper.
- Violated contract: H30 and R4; experiment 9's clearance/inconclusive requirement for a uniformly better candidate;
  the claimed confidence and heavy-tail mitigation at lines 488–498. The normal-case qualification does not
  protect the repeated-evaluation claim, and the rare-value example demonstrates the broader protection still
  missing. Expiry limits the damage's duration but does not correct the decision or its error rate.
- Suggestion: require evidence calibrated for both the allowed distributions and the actual sequential evaluation
  policy, leaving unsupported comparisons inconclusive.

## Reproduction details

Both checks ran in memory with standard-library Python, without creating test files. The rare-value calculation
enumerated Q counts 30 through 170 using sample variance (denominator `n - 1`) and computed the binomial tail
exactly with `math.comb`, then decimal precision 45. Its inputs and all formulas are specified above.

The strict-regression simulation used the following complete script; `max(1, ...)` is unnecessary for the observed
draws and was not used. Costs were positive in the executed reproduction.

```python
import math, random
r = random.Random(20261124)
N = 5000
counts = {10: {'force': 0, 'clear': 0}, 20: {'force': 0, 'clear': 0}}
first = {'force': 0, 'clear': 0}
for trial in range(N):
    ng = nc = 0
    sg = sc = qg = qc = 0.0
    first_eligible = True
    for look in range(1, 21):
        for _ in range(60):
            base = 1000 + round(100 * r.gauss(0, 1))
            if r.random() < 0.5:
                ng += 1; sg += base; qg += base * base
            else:
                cost = 2 * base + 1
                nc += 1; sc += cost; qc += cost * cost
        if min(ng, nc) < 30:
            continue
        mg, mc = sg / ng, sc / nc
        vg = (qg - sg * sg / ng) / (ng - 1)
        vc = (qc - sc * sc / nc) / (nc - 1)
        z = (mc - 2 * mg) / math.sqrt(vc / nc + 4 * vg / ng)
        decision = 'force' if z > 1.645 else ('clear' if z < -1.645 else None)
        if first_eligible:
            if decision:
                first[decision] += 1
            first_eligible = False
        if decision:
            for cutoff in counts:
                if look <= cutoff:
                    counts[cutoff][decision] += 1
            break
print(first)   # {'force': 271, 'clear': 260}
print(counts)  # 10: force 797, clear 740; 20: force 1048, clear 932
```
