### R6 — Verified resolved: deferred index creation retains an effective worker activation

Original: [2026-11-26-code.md#R6](2026-11-26-code.md#R6), major. Functional fix:
`02e3ccb23b594e349a0bb2289cea1764b1338465`. Regression-test refinements: `f55af4a`, `7def9ed`, `42d5743`.

**Causal verification:** `crates/krummi/src/lib.rs:1649-1655` activates vector maintenance after the deferred
commit has been published and enqueued. The worker consumes that activation, releases its state mutex, then calls
`Engine::make_durable` before reading the catalog (`table/vector_worker.rs:275-300`). The journal captures a fixed
`queued_upto` target and waits for it (`crates/krummi-pager/src/journal.rs:789-793`); this neither takes the
application write turn nor waits for all future commits. The journal publishes durable progress before notifying
waiters (`journal.rs:1071-1108`), and read visibility is bounded by publication and durability
(`crates/krummi-pager/src/scratch.rs:679-701`). A subsequent activation remains set for the next outer iteration.

The failing sequence can therefore no longer consume its only activation while seeing a catalog from before the
index creation. The new wait is outside the worker-state mutex and application write turn. Shutdown leaves the
journal running until the worker has joined; failed durability calls mark write refusal
(`crates/krummi-tx/src/lib.rs:436-441`), which the worker checks before its next pass. No new deadlock, publication,
rollback or index-consistency failure was established in these dependent paths.

**Independent differential reproduction:** on a fresh persistent store, insert 10,000 one-dimensional vectors;
create the first L2 index in a deferred transaction that also stores an incompressible 8 MiB value in an ordinary
tree. Call `make_durable`, open the table, wait for vector idle, sleep 20 ms and inspect again, as in the earlier
report. No journal fault or pause is injected in this probe.

Both delegated reviewer and coordinator independently observed on separate disposable stores:

```text
BASE aeed1a0: Training, pending=0, batches=0; stalled=5/5
HEAD c9d4fa8: Ready, pending=0; stalled=0/5
```

Explicit activation recovered every stalled base run. Each completed or recovered index passed
`check_vector_index`; exhaustive indexed search matched exact search in primary keys and distance bits. Probe
exits were zero because the diagnostic asserted the expected stall count separately for each revision; the base
exit is not a passing index-maintenance verdict. Final base/head runs used dependency versions and checksums
pinned to the repository's `Cargo.lock`.

Both runners also passed the head probe's lifecycle extensions: aborted index creation; an older snapshot that
continues to lack the new index; 100 deferred updates from four threads; `make_durable` while an application write
is still open; immediate explicit close or implicit drop after deferred creation; reopen without prior application
table opening; and temporary stores. Consistency and exhaustive indexed/exact comparisons passed after the
updates and reopenings.

The committed journal-pause regression test also passed independently. It waits for activation consumption and
retains a 100 ms scheduling window before resuming the journal. This is useful regression evidence, not a claim
that a fixed sleep deterministically covers every possible interleaving. The causal ordering and differential
public-API reproduction provide additional independent evidence.

This verifies the pending S1/VI4/AC-VI15 behavior, including «con la fila 10.000, el índice entrena», and the
affected VI12 lifecycle. The durable-only insertion-performance decision does not exempt deferred commits from
functional maintenance; no new performance measurements are claimed.
