### R1 — verified resolved — Persistent index writes are classified as unchanged transactions

**Original severity:** blocker. **Prior finding:** [2026-11-25-prd.md#R1](2026-11-25-prd.md#R1). **Section / IDs:** Product decisions / VI3, VI9; Validations and messages.

The original reproduction combined persistent postings, generation/progress updates and a durable rebuild request with the unchanged-transaction contract, which forbids journal writes. Target line 73 now says, “Un lote es una escritura propia del trabajador, con cambios para T10 y en el diario como cualquier otra”. Lines 141–142 distinguish searches/information from requesting a rebuild, “porque guarda la petición”. VI9's explicit no-op cases remain no-ops: they do not store a request.

This agrees with `journal-group-commit.prd.md:51` (E11), `tables-statistics.prd.md:56` (ST7: a change when it saves), and `crates/krummi-tx/src/transaction.rs:634` (the unchanged path) versus `transaction.rs:663` (commit of changed pages). Deferred worker commits use the existing journal semantics (`transaction.rs:622`); losing a suffix does not independently lose the pending-row record and its corresponding index update. The worker's separate transaction does not end application references: T8 limits invalidation to changes in the same transaction (`transactions.prd.md:37`), consistently with A10 and snapshot page lifetimes (`crates/krummi-pager/src/scratch.rs:1264`). The original persistence contradiction is removed.

### R2 — verified resolved — The k-result guarantee includes rows whose vectors cannot be returned

**Original severity:** blocker. **Prior finding:** [2026-11-25-prd.md#R2](2026-11-25-prd.md#R2). **Section / IDs:** Product decisions / VI1, VI6; Acceptance criteria / AC-VI13.

Target line 76 now defines eligible rows throughout the PRD: “las filas que **pasan** son las que cumplen el filtro y tienen el vector no nulo (VI1): son las que cuentan para el umbral y para k”. AC-VI13 at lines 249–250 explicitly covers k relational matches with one null vector: k−1 results, and that row does not count toward the threshold.

The same eligible population now determines the exact/approximate boundary. The pending-row exact evaluation in VI5 continues to cover eligible rows not yet reflected by the index; this correction does not weaken snapshot visibility or the worker-lag guarantee.
