## Findings

### R1 — major — AC-B3 requires unchanged results when affinity fallback can change them

**Location:** Acceptance criteria / AC-B3, `docs/prd/krummi/benchmark-krummi-voron.prd.md:155`; related B4 at line 36.

**Problem:** The failure test requires the same report and exit code as a run without failure, except for the core line, but does not hold measured results or other report metadata fixed. Falling back to unrestricted measurement can change rates and threshold outcomes. A conforming real run therefore need not satisfy this equality.

**Evidence:** AC-B3 says:

> Dado un fallo inyectado al preguntar por las clases, o al limitar uno solo de los procesos, entonces la ejecución termina con el mismo código y el mismo informe que sin el fallo, salvo la línea `Núcleos: desconocido`.

B4 explicitly permits the affected process, or all processes after a query failure, to measure without restriction. The motivation and `odd/tasks/table-row-reads.md:295` (L31) already show materially different pinned and unpinned results. The inherited K7 and K13 remain unchanged: `docs/prd/krummi/benchmark.prd.md:44` evaluates actual rates against 0.80 times Voron's rate, and line 50 requires exit code `1` on a missed threshold. Existing `crates/krummi-bench/src/report.rs:76` and line 100 derive both reported outcomes and the exit code from those metrics. For example, with all other thresholds satisfied, 810 versus 1000 passes; 790 versus 1000 fails and changes the full-run exit code.

**Readings allowed:**

1. A deterministic failure-handling test supplies identical metrics and metadata to both runs; only *Núcleos* changes.
2. Actual benchmark runs inject only the topology/affinity failure; the equality requirement then conflicts with legitimate measurement changes and the inherited threshold rules.

**Impact:** Implementers can disagree about whether AC-B3 requires a deterministic fixture or preservation of real benchmark outcomes. Literal equality for real measurements is not a valid acceptance oracle. This is major rather than blocker because an explicitly controlled test context makes the intended check implementable.

**Suggestion:** Specify identical injected results and report metadata for the equality assertion, while retaining evaluation of actual metrics in real runs.

**Disposition:** Open; no fix was reviewed.
