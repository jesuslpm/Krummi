### R2 — major — A writer's own flush causes a maximum-size failure without readers

**Verified resolved** by `7584790d6f0e0a3d0cda35a849edd05644eed1b1`.

The violated requirement remains J7, `docs/prd/krummi/journal.prd.md:37`:

> una escritura nunca falla por tamaño máximo a causa de versiones que ninguna lectura necesita: antes se trasladan.

**Source evidence:** `ScratchWriter::flush` waits for the requested transfer, then releases retired entries no open read can reference before returning its original outcome (`crates/krummi-pager/src/scratch.rs:1078`). Its special reclamation bound excludes the calling writer while preserving the oldest registered reader (`:891`, `:896`). `free_retired_before` retains entries unless `bound < oldest`, and decrements whole-run charges through `release` (`:901`, `:811`). The subsequent reservation check therefore sees the reclaimed budget (`crates/krummi-tx/src/transaction.rs:677`). Background transfer and snapshot destruction retain their original writer-aware bound (`scratch.rs:880`).

**Independent reproduction:** consulted the earlier `target/review-followup-j7.rs` and adapted its three-write scenario into the disposable `target/review-followup-r2-20261028-03.rs`. Under a 24 MiB maximum, with automatic transfer paused and no reads, commit a 1,040-page run, free it in a second committed write, then allocate the same run in a third write. In both disk and temporary modes, the reservation now succeeds at the same first page, releases the old exclusive allocation and reduces counted scratch bytes to zero before the third commit. That commit succeeds without growing the data area, and the entire payload reads back correctly.

| Stage, identical in disk and temporary modes | Data bytes | Counted scratch bytes | Temporary-area bytes |
|---|---:|---:|---:|
| Before the third write | 8,552,448 | 8,552,448 | 8,650,752 |
| After its forced transfer/reservation, before commit | 8,552,448 | 0 | At most one shared chunk |
| After successful commit | 8,552,448 | 8,536,064 | 8,650,752 |

The same probe also checks a 32 MiB case that keeps the original run live: the writer reads it, allocates a second run and thereby forces transfer/reclamation, then reads the first run again. Both complete payloads remain correct in that write and in a subsequent read, in both storage modes. This exercises the writer's transition from scratch-backed reads to data-backed reads after reclamation.

The committed `a_write_s_own_transfer_frees_the_runs_no_read_needs` regression (`crates/krummi-tx/tests/runs.rs:639`) also passed independently, covering both no reader and an earlier reader that ended before the reservation, on disk and in temporary mode.
