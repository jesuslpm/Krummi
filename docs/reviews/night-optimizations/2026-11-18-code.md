### R1 — minor — The draft reuses the current store-format number for an incompatible change

- Location: `docs/prd/krummi/journal/journal-skip-compression.prd.md:48` (also line 67).
- Problem: option 2(a) states «el formato pasa a `11` y los almacenes de formato `10` quedan como formato anterior». The current store format is already 11, at both base and head (`crates/krummi-pager/src/format.rs:37–41`), following E20 of `docs/prd/krummi/tables/tables-schema.prd.md:55`.
- Scenario and impact: a maintainer evaluating this option is told that format 11 is a new incompatible format and that format 10 is the current starting point. That compatibility description is false for existing format-11 stores. Implementing it literally in a later run would fail to distinguish the two incompatible layouts. No such implementation exists in this range; the demonstrated defect is the draft's inaccurate description.
- Evidence: verifiable source/requirement comparison, not an experimental failure. S3 requires a draft when stored bytes would change; the draft cites D7's format distinction, but its stated starting version contradicts the code and E20.
- Suggestion: describe the current format as 11 and assign a fresh format identifier if the incompatible option is approved.
- Status: open.
