## Findings

<a id="R1"></a>
### R1 — blocker — Reject the remaining options that commands silently ignore

**Location:** `crates/krummi-ann-lab/src/main.rs:63`; related parsing at lines 28–37 and dispatch to `run.rs:106` / `run.rs:265`.

The command parser accepts `--filas` and `--informe` globally, but its command-specific checks cover only `--sondeos` and `--metrica`. `preparar` never reads the requested row limit or report path; `verdad` never reads the report path. Both return success after omitting these explicit requests.

**Reproduction, executed against the reviewed checkout:** a disposable SIFT fixture contained five 128-dimensional base rows, one query, and valid source neighbours. With the common arguments `--carpeta <fixture> --conjunto sift`:

- `preparar --filas 2 --informe <fixture>/requested-report.md` exited 0, printed `sift: 5 vectores de 128 dimensiones y 1 consultas en 0.1 s.`, and wrote all five base rows. The report did not exist.
- `verdad --filas 5 --informe <fixture>/requested-report.md` exited 0 and generated the truth cache, while the requested report still did not exist.

On the real datasets, a preparation requested with a small limit can therefore process the full dataset, and an explicit report request can disappear without an error. This is the same failure class the last fixes already address for the other flags. The test `options_a_command_would_ignore_are_rejected` omits these combinations.

**Evidence:** executed CLI reproduction plus parser-to-handler source tracing. **Requirement:** the `review-code` rubric explicitly classifies silently ignored explicit options as a blocker when demonstrated; related flows are S3 and S5. This severity does not imply an engine-storage defect.

**Suggestion:** reject every option/command combination the handler does not implement, and cover the rejected combinations through the CLI.

<a id="R2"></a>
### R2 — major — Complete the required memory measurement and distinguish payload estimates

**Location:** `docs/benchmark/2026-11-24-ann-experiment.md:180`; related `crates/krummi-ann-lab/src/hnsw.rs:88`.

S6 requires “Memory | RSS plus the working set in the page cache”. The report explicitly says these were not measured; ODD L11 (`odd/tasks/ann-experiment.md:136`) calls this an S6 gap, while T6 is marked done. Neither measurement path collects the missing runtime memory evidence. Keeping vectors in memory does not remove their RSS.

The HNSW substitute also does not describe the memory representation being measured: `hnsw.rs:91` calculates `base.len() * 2 * M * 4`, and the output says the layer-zero links occupy that space. This becomes 122.1 MiB at one million rows. The exact locked dependency, `hnsw_rs 0.3.5`, stores per-node `Vec<Vec<Arc<PointWithOrder>>>` (`src/hnsw.rs:172`); `PointWithOrder` holds an `Arc<Point>` and an `f32` distance (lines 265–270). These are not compact four-byte IDs; allocation, reference-counting, vector capacities and node metadata are also absent from the formula.

**Failure scenario:** the one-million-row comparison supplies no observed process memory and presents an idealized compact-link payload as the external graph's link occupancy. The fallback's real memory cost cannot be assessed from those figures as S6 requires. This does not refute the preserved recall or latency results.

**Evidence:** explicit admission in the committed report and ODD, measurement-code inspection, and inspection of the locally cached source for the exact dependency version in `Cargo.lock`. No new RSS number is claimed.

**Suggestion:** provide observed memory measurements for the compared configurations and label compact-payload calculations as estimates rather than actual structure occupancy.

<a id="R3"></a>
### R3 — minor — Handle recall when fewer than k neighbours exist

**Location:** `crates/krummi-ann-lab/src/run.rs:234`; related `check_truth` at line 406 and the recall calls in `measure.rs`.

The CLI accepts every positive `--filas`, and truth validation accepts `min(TRUTH_K, rows)` neighbours. Nevertheless, recall always divides the intersection count by `expected.len() * k`. A perfect result can therefore never reach 1 when the base contains fewer than k rows.

**Reproduction, executed:** after creating the five-row truth cache above, `medir --carpeta <fixture> --conjunto sift --filas 5 --sondeos 1` exited 0. All five rows are in the only IVF list; IVF-Flat scans that complete list and finds every exact neighbour. Its output nevertheless reports recall@10 `0.5000` and recall@100 `0.0500`. The SQ8 scan and exhaustive IVF-SQ8 produce the same erroneous recall values. The five base vectors were `[1; 128]` through `[5; 128]`, with query `[1; 128]`, so the truth is unambiguous.

**Evidence:** CLI reproduction and the denominator's arithmetic. **Requirement:** S5/S6 compare approximation against exact ground truth; the public CLI admits this input. Impact is limited to inputs below the required experiment scales, so the committed 10,000/100,000/full-scale conclusions are unaffected. The current recall test covers no truth list shorter than k.

**Suggestion:** normalize by available ground-truth neighbours, or reject row counts below the supported recall cutoff.
