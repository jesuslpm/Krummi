- Severity: **minor**.

- Problem: the PRD states that the affected earlier documents already carry the annotations, but the listed annotations have not been added. The new decisions are explicit in this PRD, so this is a documentation consistency defect rather than an unresolved product choice.

Searches and inspection of the ten affected earlier PRDs found no annotations for this child or format `8`. For example, `docs/prd/krummi/trees.prd.md:91` still ends its dated annotations with 5.3, and `docs/prd/krummi/trees-keys.prd.md:68` still has the format `7` annotation. - Status: **open**.

<a id="R2"></a>
### R2 — The format-change rationale describes an unsupported deletion path

- Severity: **minor**.
- Section / ID: *Decisiones de producto / M14*; `docs/prd/krummi/trees-multivalue.prd.md:53`.
- Problem: M14 explains the format bump using a successful deletion that would leak the multivalue subtrees. The inspected format `7` implementation rejects an unknown catalog type before reaching that deletion path. Format `8` is already an explicit decision; the defect is the factual rationale, not the decision itself.
- Evidence: M14 says that an older engine “al vaciar, borrar o sobrescribir con Renombrar un árbol multivalor no liberaría las páginas de sus subárboles, que quedarían retenidas para siempre”. However, `Entry::decode` rejects unknown kinds in `crates/krummi-tree/src/catalog.rs:58`, and `decode_in` reports damage at `:71`. `delete_tree` reads the catalog before deleting (`crates/krummi/src/lib.rs:394`), and `rename_tree` looks up both source and destination before deleting the destination (`:409`, `:415`). Opening in the mutating modes also first consults the catalog (`:363`). Thus the asserted partial-free path is not supported by the current reader; the future internal representation is still left to implementation.
- Suggestion: justify M14 using the demonstrable incompatibility and remove the unsupported leak scenario.
- Status: **open**.
