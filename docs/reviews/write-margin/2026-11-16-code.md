The harness alternates build order, uses the benchmark's performance-core launcher and checks digest equality. - **Version and causal limits:** L8 identifies the measured head as `fdb7af9`, before final head `1ee31df`. The later code commit changes the replacement guard and tests; it contains no declared W20 fix or final-head non-regression measurement. Thus the documented regression remains unresolved, but this review does not claim that final head was independently measured as slower. The proposed code-layout cause is unproven; neither the hash nor the version mark is established as its cause.
- **Requirement:** S4. Lower impact than corruption or a functional failure, but a substantive acceptance gap in a performance-only change.
- **Suggestion:** resolve the W20 regression and repeat the A/B on final head; accepting a write-speed/read-speed tradeoff instead requires an explicit user change to S4.

## Pre-existing advisory outside the introduced-defect verdict

<a id="R2"></a>
### R2 — pre-existing advisory — reused ScratchWriter snapshots are omitted from version GC

**Location:** `crates/krummi-pager/src/scratch.rs:1051`; the new mark inherits this lifetime limitation at `crates/krummi-pager/src/scratch.rs:1228`. Classification: pre-existing memory-safety advisory, non-blocking for this commit range, not an additional introduced finding.

The safety argument assumes that every snapshot retaining a version also retains its slot. `collect_garbage` considers `state.live` but omits `state.writer`. The following low-level safe-API sequence violates that assumption:

1. In a temporary `Scratch::new`, retain a reader at tx0 and publish version v1 of page P.
2. Open a reader and a writer at tx1. Publish v2 using that writer, then obtain v1 and its mark through `writer.snapshot().page_and_code(P)`. The reader at tx1 keeps v1 until this read.
3. Drop the reader at tx1 while retaining the writer and mark, then call `scratch.transfer()`.
4. GC sees only the reader at tx0, which does not need v1, and removes v1 directly. `drop(garbage)` at `scratch.rs:792` releases its `Arc<Slot>`. Using the retained mark then accesses the freed `AtomicBool`.

This is a verifiable technical argument, not an executed use-after-free reproduction. `publish(&mut self)` at `scratch.rs:1508` leaves the writer's snapshot txid unchanged; reading after publication is expressly covered by `scratch_tests.rs:189`. `transfer(&self)` at `scratch.rs:526` does not borrow the writer mutably, so it does not end the outstanding mark's borrow.

**Base comparison:** the same GC omission, reusable writer and unowned page borrow exist at `6b49bea`. Before this range they already allow slots to be freed/reused while references to their page bytes remain borrowed. The root retention defect is therefore pre-existing, rather than a new blocker attributed to the mark optimization. No corresponding sequence was established through normal `Store` operations: `WriteTransaction::commit(self)` consumes and drops its writer (`crates/krummi-tx/src/transaction.rs:510`, `:549–569`). Relevant contracts are root D12, pager P16 and snapshot lifetime/retention rules.

Suggestion: review low-level writer retention or the post-publication `ScratchWriter` contract separately. This advisory is not part of the open introduced findings used for this review's approval decision.
