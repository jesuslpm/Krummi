## Finding verification

### R1 — The pause helper does not acknowledge an already-dispatched transfer

- Original severity: **minor**, pre-existing advisory.
- Status: **verified resolved** at the reviewed head by the two fix commits above.
- Original evidence: a source-based concurrency scenario, not an experimental reproduction. The worker could return `Work::Pass`, then be descheduled before taking `flushing`; the old pause could return before that pass wrote and consumed AC-E13's injected journal-writer panic.
- Relevant locations: `crates/krummi-pager/src/transfer.rs:189`, `:215`, `:257`, `:299`, `:310`, `:342`; unchanged wrapper at `crates/krummi-pager/src/scratch.rs:593` and AC-E13 at `crates/krummi-tx/tests/group_commit.rs:181`.

**Independent verification:** dispatch now sets `passing=true` while holding the same signal mutex that protects `paused`. If pause wins that mutex, no automatic pass is selected; if dispatch wins, pause observes `passing` and waits on `answered`, releasing the mutex while waiting. Successful and failed passes reach `after_work`, which clears `passing` under that mutex and wakes pause callers. Consequently, the original scheduling window cannot let an already-dispatched automatic pass write after pause returns.

A panic skips `after_work`, but the worker's `Alive` guard sets `alive=false` under the same mutex and notifies `answered`; the pause predicate then stops waiting. The same synchronization prevents a lost wakeup. Pausing again after thread termination does not wait on a stale `passing` flag. The existing `flushing` barrier remains in the public helper.

The added test directly constructs the original precondition: `next_work` has selected a pass before pause is requested. It verifies blocking until normal completion and until worker termination, then verifies another pause after termination. This test passed independently, as did AC-E13, which still verifies the journal writer's failure, rejected writes and recovery of a previously returned commit. Its authoritative criterion states:

> Dado un fallo simulado al poner en marcha lo que escribe el diario, cuando se abre el almacén,
> entonces falla con la clase de memoria agotada y el almacén queda idéntico byte a byte; y dado un fallo simulado
> de ese mecanismo con confirmaciones esperando, entonces fallan con la clase de entrada y salida, las peticiones
> siguientes también, y al reabrir están todas las que habían devuelto sin error (E13).

**Regression assessment:** explicit demands remain serviceable during pauses, as required by the transfer ODD. Normal production scheduling, pacing, retry decisions, durable-version selection, transfer ordering, write exclusion and shutdown ordering remain intact. The new wait does not hold the signal mutex while the worker completes its pass. Existing pause callers do not introduce a lock inversion with this wait. Source analysis and the checks below found no regression caused by the fixes.
